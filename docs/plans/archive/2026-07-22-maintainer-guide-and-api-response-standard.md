# 人类维护指南、函数风格与统一 API 响应实施计划

## 目标

让不熟悉 OpenAPI、Drizzle 和 Vitest 的全栈维护者能够独立理解和修改项目；统一命名函数风格、业务响应、分页约定和错误码治理。

## 非目标

- 不新增实际分页业务接口。
- 不在本轮引入认证体系或具体业务模块错误码。
- 不改变 Swagger UI 等基础设施接口的原始响应格式。

## 实施任务

- [x] 定义共享普通响应、分页响应和分页请求 TypeScript 类型。
- [x] 定义错误码常量、响应辅助函数和 Fastify 全局错误处理。
- [x] 修改 `/health` OpenAPI、后端返回和前端消费方式。
- [x] 增加响应辅助、404、错误处理和分页默认值测试。
- [x] 将有名称的箭头函数改为函数声明，并记录风格规则。
- [x] 编写详细人类维护者开发指南和错误码参考文档。
- [x] 生成类型并运行测试、构建、数据库和文档验证。
- [x] 更新最终设计、AI 日志并归档计划。
- [x] 提交全部验证通过的改动。

## 验证

- `/health` 返回 `{ status: 0, data: ... }`。
- 未知路由和未捕获错误返回带非零错误码的统一结构。
- 分页默认值和分页响应辅助函数有单元测试。
- OpenAPI 与 Fastify Swagger 契约测试通过。
- `pnpm test`、`pnpm build`、`pnpm test:db` 全部通过。
- 人类指南中的内部链接和命令与项目现状一致。

## 回滚

响应结构是破坏性接口变更，回滚必须同步恢复 OpenAPI、前端消费、后端实现和测试，不能只恢复单侧代码。

## 实际结果

- 新增共享 `ApiResponse<T>`、`PaginationRequest`、`PaginatedResponse<T>` 及后端响应辅助函数。
- `/health` 已返回 `{ status: 0, data: { status, timestamp } }`，前端按传输错误和业务状态两层处理。
- 未知路由和未捕获异常分别返回 1003、9000 的统一错误结构。
- 生产源码中的命名箭头函数已改为函数声明；测试和框架短回调继续允许箭头函数。
- 新增详细维护者指南、错误码参考和 ADR-0003。
- `pnpm gen:api`、后端 10 个测试、前端 6 个测试、`pnpm build` 和 `pnpm test:db` 均通过。
- Vite 仍报告 CJS Node API 弃用警告，不影响本轮构建结果。
