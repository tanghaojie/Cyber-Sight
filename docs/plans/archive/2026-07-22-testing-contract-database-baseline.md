# 测试、统一接口类型与 PostgreSQL 开发环境实施计划

## 目标

清理无用后端文件，建立前后端测试基线，将 API 类型统一到共享契约包，安装全部依赖，并连接用户本机 PostgreSQL 完成迁移和验证。

## 非目标

- 不同时实现 Java 后端。
- 不在本轮引入完整端到端浏览器测试和 CI。
- 不把本机数据库凭据写入受版本控制文件。
- 不创建用户未指定的新数据库。

## 实施任务

- [x] 确认 `sensible.ts` 无引用后删除。
- [x] 分离后端应用组装和进程启动，增加 Fastify 路由测试。
- [x] 增加 Vue 组件测试和测试命令。
- [x] 将 OpenAPI 生成类型迁移到共享 workspace 包。
- [x] 让前端和后端消费同一份生成类型。
- [x] 增加 OpenAPI 与 Swagger 契约测试。
- [x] 集中加载并校验后端环境变量。
- [x] 增加数据库迁移、连接检查和生命周期关闭逻辑。
- [x] 安装全部依赖并更新锁文件。
- [x] 写入本地忽略的 `.env`，执行 PostgreSQL 迁移。
- [x] 运行类型生成、测试、构建和数据库连接验证。

## 风险

- 本机 PostgreSQL 中可能已有同名表或对象；迁移前先检查连接和当前 Schema。
- Fastify Swagger 输出与 OpenAPI 表达可能存在等价但结构不同的字段，契约测试应比较稳定语义而不是整个 JSON 文本。
- 依赖升级不在范围内，只安装并补充完成任务所需依赖。

## 验证

- 默认测试不依赖真实数据库且全部通过。
- 前后端不再维护各自独立的 TypeScript API 类型。
- 契约漂移会导致测试失败。
- `pnpm build` 全部通过。
- 数据库连接检查成功，迁移记录和示例 `users` 表可查询。

## 回滚

代码可通过 Git 恢复；本地 `.env` 可删除。数据库迁移若创建了新表，回滚必须先确认其中没有用户数据，不能自动执行破坏性删除。

## 实际结果与偏差

- 用户在 Codex 安装多次受 Windows I/O 和网络影响后手动完成了依赖安装，并补充了 pnpm 构建许可配置。
- PostgreSQL 18.4 连接成功；迁移前 `users` 和 Drizzle 迁移表均不存在，迁移后已创建。
- 后端 2 个测试、前端 4 个测试全部通过；生产构建通过。
- Vitest/Vite 在 Codex 沙箱中解析 Windows 上级路径受限，最终验证在用户批准的沙箱外命令中完成。
- 最终构建发现 `vue-tsc` 会向源码目录发射 JavaScript，已通过 `noEmit` 修正并清理生成物，复验构建不再污染源码。
- 运行时 Schema 自动生成没有纳入本轮，继续由共享类型和契约测试控制漂移。
