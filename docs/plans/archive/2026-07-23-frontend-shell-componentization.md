# 前端应用壳组件化与动态页面加载

## 目标

引入 Tailwind CSS 和 Element Plus，将管理端拆分为侧栏、顶栏、动态内容区和独立页面组件，并确保点击菜单后通过嵌套路由懒加载中间页面。

## 背景与设计依据

现有 `AdminLayout.vue` 同时承担导航、顶栏和内容区，页面样式主要由手写 CSS 构成。实现遵循[前端应用壳设计](../../design/frontend-shell.md)和 [ADR-0008](../../decisions/ADR-0008-tailwind-and-element-plus.md)。

## 范围

- 安装并配置 Tailwind CSS、Element Plus 和图标依赖。
- 拆分应用壳组件和集中导航模型。
- 使用嵌套路由与懒加载实现菜单驱动的动态内容区。
- 重构首页和现有管理资源页，使其融入新的组件与视觉体系。
- 增补组件/路由测试并完成桌面、窄屏视觉检查。

## 非目标

- 不修改后端 API、共享契约、认证策略或数据库。
- 不新增细粒度 RBAC、服务端动态菜单或新业务模块。
- 不在本轮建立完整暗色主题。

## 前置条件和风险

- Element Plus 会增加前端产物体积；先采用完整注册保证实现清晰，后续可按实际体积需求引入自动按需导入。
- 样式迁移可能影响现有测试选择器和小屏布局，需要同时运行组件测试与浏览器检查。

## 实施任务

- [x] 更新前端依赖和 Vite/Tailwind 配置。
- [x] 创建导航模型、侧栏、顶栏和动态内容区组件。
- [x] 重构布局、首页、登录页和管理资源页面的视觉与交互。
- [x] 增补测试并修复回归。
- [x] 完成构建和浏览器视觉验证。
- [x] 更新最终设计、AI 日志与索引并归档计划。

## 测试与验证

运行 `pnpm --filter @scaffold/frontend test`、`pnpm --filter @scaffold/frontend build`，并在本地开发服务器检查桌面与窄屏下的登录、菜单切换、侧栏开关和资源页状态。

## 发布与回滚

本次只影响前端。回滚时恢复前端依赖、Vite 配置、应用壳组件和样式文件即可，不涉及数据迁移。

## 实际偏差和遗留问题

- 初版完整注册 Element Plus 时主入口约为 1,040 kB；最终增加自动按需导入，主入口降至约 114 kB，资源页保持独立异步分块。
- 资源页继续使用配置驱动的单页面实现，但应用壳、导航模型、Header、Sidebar 和 Main 已拆分；若各资源后续出现显著不同业务行为，再拆为独立页面。
- 构建成功，Vite 仍提示来自现有 CJS 测试配置和第三方 `@vueuse/core` 注释的非阻塞警告。
- 未使用真实账号执行浏览器登录；认证后应用壳由组件测试、类型检查和生产构建验证。
