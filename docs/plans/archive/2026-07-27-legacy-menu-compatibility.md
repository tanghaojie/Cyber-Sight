# 旧菜单数据兼容与导航容错

## 目标

修复升级动态菜单后，旧版菜单记录导致菜单管理接口 500、无效节点进入左侧导航的问题。

## 背景与设计依据

旧版菜单写入只校验字段长度，不约束编码格式及不同节点类型的字段组合。新版把目录、站内菜单和外链按钮改为严格判别联合后，读取响应误用了写入约束，导致存量不规范记录使整个菜单列表无法序列化。

## 范围

- 区分菜单写入契约与兼容性读取契约。
- 导航树过滤无法实际打开的站内菜单与外链按钮。
- 为直接打开动态 URL 增加启动阶段兜底匹配，避免应用壳短暂空白。
- 增加存量无效菜单的契约及树构造回归测试。
- 使用当前本地数据库复现并验证修复。

## 非目标

- 不自动猜测旧菜单应映射到哪个 Vue 页面或外部网址。
- 不删除、覆盖或静默改写用户已有菜单记录。
- 不放宽新增和编辑菜单时的严格校验。

## 前置条件和风险

读取接口必须保留旧记录，确保管理员能在菜单管理页看到并修正；无效记录不得进入运行时导航。若旧站内菜单缺少组件标识，只能由管理员补充，系统不能安全推断。

## 实施任务

- [x] 调整共享菜单摘要 Schema，允许读取旧记录。
- [x] 在导航树构造阶段过滤不可打开的菜单节点。
- [x] 增加契约与导航回归测试。
- [x] 修复动态路由首次装载前的未匹配空白状态。
- [x] 修复窄视口下 `AppSidebar` 首次进入默认隐藏的问题。
- [x] 验证真实菜单接口、页面、全仓测试和生产构建。

## 测试与验证

- 单元测试覆盖小写旧编码、空外链按钮、缺少组件的站内菜单。
- Fastify 真实数据库注入验证 `/navigation/menus` 与 `/admin/menus/tree`。
- 浏览器验证左侧菜单存在、无效外链不展示、菜单管理能显示旧记录。
- 浏览器直接刷新 `/menus` 时不产生未匹配警告，未知路径仍进入 404。
- 布局测试确认 `AppSidebar` 首次渲染为展开状态，小屏仍可主动关闭。
- 执行 `pnpm test` 和 `pnpm build`。

## 发布与回滚

本次不修改数据库数据，无需迁移。回滚代码即可恢复原行为，但旧记录会再次触发菜单管理 500。

## 实际偏差和遗留问题

排查时确认并非数据库迁移缺失，而是三项叠加问题：旧记录不满足新版读取 Schema、动态 URL 首次匹配缺少兜底、侧栏状态默认关闭且依赖 1024px 媒体查询。最终未修改数据库数据，旧 `test` 记录仍保留在菜单管理中等待管理员修正，但已不会进入运行时导航。

验证结果：真实数据库 Fastify 注入下 `/navigation/menus` 与 `/admin/menus/tree` 均返回 HTTP 200；浏览器确认左侧有效菜单与 9 条管理记录正常显示，空外链不再进入导航，直接打开 `/menus` 无控制台警告；布局回归测试确认 `AppSidebar` 首次渲染为展开。`pnpm test` 通过后端 41 项、前端 24 项及契约类型检查，`pnpm build` 成功。
