# 接口日志持久化与查询

## 用户目标和约束

实现所有业务 API 的接口日志持久化并供管理员查看。登录成功与失败永久保留；其他业务日志保留 90 天后自动删除。排除健康检查与 Swagger；记录 404、401 和权限拒绝。用户删除仍为软删除，无需永久日志。日志可丢失，但绝不能影响系统正常请求；不接入外部日志采集，也不保存 body 等复杂信息。

## 关键问答与确认

- 登录永久日志包含成功与失败；退出和未来刷新会话使用 90 天保留期。
- 登录失败保留尝试的用户名，但不保存密码。
- `/health`、`/docs` 及其子路径不记录。
- Pino 只记录内部持久化或清理错误，不增加监控指标或采集系统。

## AI 的重要假设

对无匹配路由的 404 保存固定未匹配标识而非原始 URL。所有未明确排除的已匹配业务路由默认保留 90 天。日志队列满时优先丢弃普通日志，永久登录日志尽力保留但在极端故障下也允许丢失。

## 方案和执行摘要

新增 `system/api-logs`，以 Fastify Hook 采集最小元数据，经有界内存队列批量写入 PostgreSQL。以 `expires_at IS NULL` 表示永久记录，日常任务物理删除过期普通记录。新增 `api_logs.read` 权限和管理员分页查询 API。

## 验证结果

通过 `pnpm format`、`pnpm lint`、`pnpm test`（13 个测试文件、109 项测试）、`pnpm build` 和 `pnpm format:check`。未运行 `pnpm test:db`，因为没有独立空 PostgreSQL 数据库可安全使用。Drizzle 生成迁移时额外包含无关的角色列删除语句，已移除后再通过迁移静态测试。

## 未决问题与下一步

无。后续可在前端消费 `GET /admin/api-logs` 建立管理员查看页面。
