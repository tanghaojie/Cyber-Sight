# 主题颜色与深色模式协作记录

## 用户目标

保留已确认的翡翠绿、政务红、高级黑白灰、智蓝、灵感紫、琥珀橙六种主题颜色；实现系统主题色、深色模式及设置弹窗中的即时切换。

## 关键事实与假设

- `settings` 已保存主题颜色与深色模式，但当前设计明确这两项尚未驱动视觉效果。
- 偏好保持设备级浏览器存储，不新增后端、数据库或 API 契约。
- 既有的四个主题值应映射到语义相近的新值，以避免因枚举扩展重置其他设置。

## 方案

设置模块在应用根部挂载主题控制器，把主题标识和深色状态同步到 `html`；全局 CSS 与 Element Plus 从主题令牌读取颜色。设置弹窗只调用已登记的 Store 公共接口，因此每次选择会即时持久化并触发响应式更新。

## 实际改动

- 增加 `settings.theme.ts` 统一定义六种主题及旧版值映射，新增 `ThemeController.vue` 统一处理应用根主题副作用。
- 更新全局、Element Plus、管理表面、Header、顶部导航、Tags View 与系统设置弹窗的主题令牌消费。
- 设置弹窗改为翡翠绿、政务红、高级黑白灰、智蓝、灵感紫和琥珀橙，并同步中英文文案。

## 验证记录

- `pnpm format`、`pnpm format:check`、`pnpm lint`、`pnpm build` 通过。
- ESLint 初次在受限沙箱因 Node 运行时路径读取失败；按权限流程重试后通过。
- 未创建或运行前端自动化/浏览器测试，符合前端人工验收边界。生产构建仅保留既有分包和 Sass 弃用警告。

## 未决问题

维护者需人工确认六种主题、深色模式、移动抽屉与浏览器刷新恢复的实际视觉效果。
