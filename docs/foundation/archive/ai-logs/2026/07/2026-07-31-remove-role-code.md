# 移除角色编码

## 用户目标和约束

用户确认角色编码没有业务意义，要求从前端、后端和数据库删除，并要求顶部栏展示全部角色名称。

## 关键问答与确认

- 当前角色授权、用户角色归属和数据策略通过 `roleId` 关联；`roleCode` 未参与运行时授权。
- `roleId` 是内部关联标识，不应展示；认证快照需要携带角色 ID 和角色名称，顶部栏仅显示名称。

## AI 的重要假设

- 仓库文档声明当前只维护面向全新空数据库的单一初始基线，因此本次同步更新 `0000` 初始迁移及其唯一快照，而不添加旧库升级迁移。
- 角色名称可以作为空数据库初始种子中定位超级管理员角色的条件；该条件不构成运行时角色特殊逻辑。

## 方案和执行摘要

- 从 `sys_roles`、Drizzle Schema/快照和唯一索引中移除 `code`；全新空库的初始种子改按初始角色名称定位角色。
- 角色管理契约、仓储、表单、列表、搜索、选项类型和本地化文案不再处理编码。
- 认证身份快照改为角色 `{ id, name }` 数组；后端按角色 ID 排序，顶部栏拼接并展示全部名称。
- 后端测试同步验证无角色编码列、无角色编码索引和新的认证角色结构。

## 验证结果

- `pnpm format`、`pnpm test`、`pnpm build`、`pnpm lint` 和 `pnpm format:check` 全部通过；`pnpm test` 覆盖 100 项后端测试。
- 未执行 `pnpm test:db`：没有确认可安全使用的空 PostgreSQL 数据库。前端浏览器行为按项目约束留给维护者人工验收。

## 未决问题与下一步

前端交互由维护者人工验收：拥有多个角色的用户在顶部栏应看到以顿号分隔的全部角色名称。
