# 实现前端运行时中英文切换

## 用户目标和约束

- 脚手架默认中文，但运行时界面需要支持中文和英文切换。
- 多语言能力必须作为独立模块。
- 只翻译运行时界面，不翻译 README、设计文档、源码注释和 Swagger。
- 自定义菜单 `name` 和其他用户录入数据保持原样。
- 不增加数据库字段，不修改数据库、后端或 API 契约。

## 关键问答与确认

- 用户确认采用纯前端运行时本地化设计。
- 默认系统菜单允许通过前端严格指纹识别后翻译；自定义或被编辑的菜单显示原始 `name`。
- 语言默认中文，选择保存在浏览器，不做账号级同步。

## AI 的重要假设

- 使用 BCP 47 代码 `zh-CN` 和 `en-US`。
- 登录前后都应能够切换语言，入口位于登录页和管理端 Header。
- 代码定义且具有稳定键的权限、范围和组件目录属于固定界面文案；数据库用户数据不属于。
- 现有 tag view 存储结构保持不变，由显示层重新解析路由标签。

## 方案和执行摘要

- 新增 localization 系统模块，自动发现 system/biz 模块的 `*.locales.ts`，以中文资源键集合
  编译期约束英文资源，并公开 Vue 插件、组合式函数、Provider 和切换器。
- 使用 Vue I18n 连接 Vue、Element Plus、日期格式、`<html lang>`、浏览器标题和版本化
  `localStorage` 语言偏好。
- 登录、应用壳、工作台、错误页、标签导航、授权编辑器和五个管理模块的固定界面文案已迁移
  到所属模块资源；健康状态和共享前端提示也使用当前语言。
- 默认导航使用类型、完整路径、组件和初始名称的完整指纹；未匹配节点只返回数据库 `name`，
  不修改导航 Store、数据库或契约。
- 静态和动态路由保存本地化标签描述，应用壳按当前语言解析页面标题、路径和 tag view；
  `cyber_tag_view_history:v1:<userId>` 结构保持不变。
- 语言切换器沿用 CYBER 的工业仪表视觉，在登录页和 Header 使用同一公共组件。

## 验证结果

- 开始修改前 `git diff --cached --quiet` 通过。
- `pnpm format`、`pnpm lint`、`pnpm format:check` 通过。
- `pnpm build` 通过，覆盖 API 契约、后端 TypeScript、前端 `vue-tsc` 和 Vite 生产构建。
- 前端源码中文检索已逐项复核：剩余中文为注释、品牌专名、回退文案、默认菜单指纹和开发期
  注册错误，不属于遗漏的固定运行时文案。
- 按仓库边界未创建或运行前端自动化、组件或浏览器测试；人工交互验收仍由维护者完成。

## 未决问题与下一步

无实现阻塞。维护者需按设计清单人工验收语言切换、刷新恢复、窄屏布局、默认菜单翻译以及
自定义菜单名称原样显示。
