# 默认菜单迁移基线修正协作记录

## 用户目标和约束

- 根节点为 `menu` 或 `directory` 时必须有以 `/` 开头的路径。
- 删除数据库默认“工作台”和“首页”，首页继续由静态路由提供。
- `组织与权限` 使用 `/sys` 与 `AdminLayout`。
- `系统配置` 使用 `/config` 与 `AdminLayout`。
- 五个管理子菜单使用不以 `/` 开头的相对路径。
- 重新制作单一迁移基线，维护者会重建数据库。

## 关键问答与确认

维护者已明确接受再次重建数据库，不需要生成旧库更新迁移。

## AI 的重要假设

- 继续保留一个 `0000` 迁移，直接修正最终种子，而不是新增 `0001`。
- 子菜单的一般规则仍允许绝对路径覆盖父路径；本次只要求默认五项使用相对路径。
- `button` 不属于本次根节点路径规则变更。

## 方案和执行摘要

静态 `/` 路由直接渲染 `HomePage`；现有 `isValidMenuPath()` 已拒绝根级 menu/directory 的空路径和相对路径。修正 `0000` 菜单种子，只保留 `/sys`、`/config` 两个 `AdminLayout` 根目录及五个相对子菜单，并同步导航树、路径契约和迁移测试。

## 验证结果

- 定向测试 12 项、全量后端测试 99 项、lint 和生产构建通过。
- Drizzle 确认 14 张 `sys_` 表无结构漂移，没有新增迁移。
- 临时空 PostgreSQL 数据库执行基线后得到 7 条菜单、7 条角色菜单关系和 1 条迁移记录，随后已删除临时库。
- 生产构建仅报告既有 Sass legacy API 和重复导入警告。
- 未运行前端自动化测试，按仓库约定交由维护者人工验收。

## 未决问题与下一步

无。维护者需使用全新数据库执行修正后的 `0000` 基线，不能复用已执行旧基线的数据库。
