# 前端应用壳组件化与动态页面加载

## 用户目标和约束

用户要求当前重点处理前端，偏好 Tailwind CSS 和 Element Plus，并希望系统模块组件化：左侧菜单、顶部 Header、中间动态内容区等。点击菜单时，中间区域应动态加载对应页面。

## 关键问答与确认

用户明确允许引入 Tailwind CSS 和 Element Plus，无需保留“纯手写 CSS、无 UI 框架”的旧约束。

## AI 的重要假设

- 菜单动态加载采用 Vue Router 嵌套路由和异步组件，不在客户端拼接任意组件路径。
- 本轮保持现有前端固定导航模型，不扩展为服务端权限菜单。
- 不修改现有认证和管理 API 行为。

## 方案和执行摘要

采用深墨绿、暖灰和黄绿色强调的“精密工作台”视觉方向。应用壳拆分为 Sidebar、Header 和 Main，导航定义集中维护，业务页面通过 `RouterView` 懒加载。资源页迁移到 Element Plus 的表格、分页、输入、反馈和弹窗组件；Element Plus 使用按需自动导入，Tailwind CSS 负责主要布局和视觉样式。

## 验证结果

- `pnpm test`：通过；共享契约 1 个 TypeScript 测试任务、后端 35 个测试、前端 21 个测试全部通过。
- `pnpm build`：通过；共享契约、后端和前端生产构建成功。
- 前端按需构建主入口约 113.69 kB（gzip 44.67 kB），资源页保持独立异步分块。
- 浏览器检查桌面登录页和 390×844 窄屏登录页，无横向溢出、控制台错误或布局异常。

## 未决问题与下一步

- 本轮未用真实账号提交登录，认证后壳层交互由组件测试和构建覆盖。
- 后续可增加独立的前端端到端测试，覆盖真实登录、移动端侧栏开关和菜单页面切换。
- Vite CJS API 与第三方纯注释提示为非阻塞构建警告，可随构建工具升级处理。
