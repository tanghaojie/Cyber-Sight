# 导航抽屉行为修正

## 目标

恢复窄屏抽屉式侧栏，并让侧栏打开/关闭按钮在所有断点可用。

## 背景与设计依据

上一轮误将窄屏理解为固定侧边栏。现按维护者澄清：窄屏只切换为侧边导航呈现方式，不应常驻显示侧栏；需要始终显示的是导航开关。

## 范围

- 恢复侧栏抽屉、关闭按钮和遮罩。
- 保留桌面端保存的固定侧边/顶部导航风格。
- 让 Header 菜单按钮在所有屏幕宽度保持可用。

## 非目标

- 不改变系统设置存储格式、菜单数据、权限规则或路由。
- 不新增前端自动化或浏览器测试。

## 前置条件和风险

- 窄屏覆盖不得写回桌面偏好。
- 固定侧边布局和抽屉侧边布局必须使用不同定位与关闭语义。

## 实施任务

- [x] 分离固定侧边栏与抽屉侧边栏状态。
- [x] 恢复开关、关闭与遮罩交互。
- [x] 格式化、类型检查和生产构建。
- [x] 归档计划与 AI 协作记录并提交。

## 测试与验证

执行 `pnpm format`、`pnpm format:check`、`npx vue-tsc --noEmit` 和前端生产构建；由维护者人工验收桌面两种风格、窄屏抽屉开关与偏好恢复。

## 发布与回滚

变更仅限前端应用壳。回滚提交即可恢复上一版固定窄屏侧栏。

## 实际偏差和遗留问题

无功能偏差。前端自动化与浏览器测试不在仓库维护范围内，交互由维护者人工验收。
