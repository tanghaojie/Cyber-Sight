# 文档上下文压缩与统一归档

## 目标

审计 `docs/` 的现行性和重复度，压缩 AI 默认阅读面，并建立默认不读取、必要时可追溯的统一历史归档目录。

## 背景与设计依据

当前共有 79 份文档、约 5,438 行、255 KB。历史计划和 AI 日志占 35 份，4 份已取代 ADR 仍位于当前决策目录，部分系统设计与模块设计重复。实施依据[分层文档与历史归档](../../design/documentation-governance.md)和 [ADR-0016](../decisions/ADR-0016-tiered-documentation-and-archive.md)。

## 范围

- 建立 `docs/archive/{design,decisions,plans,ai-logs}` 和统一索引。
- 归档已取代 ADR、完成计划、完成日志和被合并的设计文档。
- 压缩根入口、系统概览、模块边界、前端应用壳及各索引。
- 更新 `AGENTS.md` 的最小阅读协议和任务结束归档路径。
- 修复迁移后的 Markdown 相对链接并记录前后体量。

## 非目标

- 不修改业务代码、API、数据库或依赖。
- 不删除历史证据，不根据文件日期自动判断有效性。
- 不重写仍有效 ADR 的原始决策理由，除状态或链接纠错。

## 前置条件和风险

- 已通过 `git diff --cached --quiet`，开始时暂存区和工作区均为空。
- 最大风险是把仍有效规则误归档；以当前代码、模块设计、ADR 替代关系和索引交叉确认。
- 批量移动后必须验证所有相对链接，不能只验证当前区。

## 实施任务

- [x] 盘点文件、行数、状态、重复内容和引用关系。
- [x] 定义当前区、活动记录和历史归档的生命周期。
- [x] 创建归档目录并迁移历史文档。
- [x] 合并重复设计，压缩默认入口和当前索引。
- [x] 更新仓库级 AI 阅读与归档规则。
- [x] 验证链接、状态、体量、工作区差异和文档一致性。
- [x] 标记计划完成，归档计划与日志并创建提交。

## 测试与验证

- 自定义 Markdown 相对链接检查覆盖整个仓库：`0` 个断链。
- 现行 ADR 全部为 `accepted`，归档 ADR 全部为 `superseded`；归档设计全部为 `archived`。
- 完成前活动区仅包含本任务计划与日志；完成后两者一并归档。
- 当前区从 79 份、5,438 行、255,423 字节降为 39 份、2,009 行、101,154 字节。
- 入口路由集从 403 行、24,213 字节降为 225 行、11,299 字节。
- `git diff --check` 通过；只有仓库既有的 LF/CRLF 转换提示。本任务不改变运行时代码，因此未运行全仓业务测试。

## 发布与回滚

这是仓库内路径迁移。若外部链接受影响，可用 Git 恢复原路径；仓库内链接在同一提交中完成迁移。

## 实际偏差和遗留问题

压缩前的系统概览、模块边界和前端应用壳作为历史快照保留在 `archive/design/`；管理系统汇总设计和动态导航设计因内容已被当前模块/应用壳设计覆盖，也一并归档。ADR-0003 只有 HTTP 策略和契约表达被后续 ADR 调整，统一响应、分页和错误码仍有效，因此把错误的 `superseded` 状态纠正为 `accepted`。

除 Git 行尾提示外无遗留问题。关联提交为本计划归档所在的最终提交。
