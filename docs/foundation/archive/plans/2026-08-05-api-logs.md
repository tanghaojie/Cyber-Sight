# 接口日志持久化与查询

## 目标

实现业务 API 的最小接口日志、登录日志永久保留、其他日志 90 天自动删除，以及管理员受权分页查看接口。

## 背景与设计依据

依据 [接口日志模块设计](../../design/modules/api-logs.md)、[后端模块设计](../../design/modules/backend.md)、[模块边界](../../design/module-boundaries.md) 和 [数据库 Schema 与迁移基线](../../design/database-schema-and-migrations.md)。

## 范围

- 新增 API 日志表、迁移、共享契约和 `system/api-logs` 后端模块。
- 注册 Fastify 生命周期 Hook、有界队列、批量写入和保留期清理。
- 新增查询 API、权限键和超级管理员种子授权。
- 覆盖后端和迁移测试，更新现行设计与协作记录。

## 非目标

- 前端日志页面、外部日志采集、监控平台、消息队列、请求/响应 body 存储和永久用户删除审计。

## 前置条件和风险

- 日志允许在数据库不可用或队列饱和时丢失，绝不阻塞业务响应。
- 登录尝试仅记录用户名，不记录密码或其他请求体字段。
- 当前迁移基线已在共享环境使用，必须追加迁移而非改写 `0000` 基线。

## 测试与验证

执行 `pnpm format`、`pnpm lint`、`pnpm test`、`pnpm build` 和 `pnpm format:check`。有独立空 PostgreSQL 环境时，额外执行迁移和 `pnpm test:db`；不使用维护者已有数据库。

## 发布与回滚

先执行追加迁移再部署应用。回滚应用时保留新增日志表，不删除历史日志；如需回滚 Schema，另行制定数据保留与权限回滚方案。

## 实际偏差和遗留问题

实现与计划一致。Drizzle 自动生成的迁移包含与本任务无关的 `DROP COLUMN IF EXISTS sys_roles.code`，已在提交前移除；迁移只创建接口日志表、索引及 `api_logs.read` 超级管理员授权。

验证通过：`pnpm format`、`pnpm lint`、`pnpm test`（13 个测试文件、109 项测试）、`pnpm build` 和 `pnpm format:check`。未运行 `pnpm test:db`，因为没有以独立空 PostgreSQL 数据库为目标的环境；该限制不影响不连接数据库的快速测试。
