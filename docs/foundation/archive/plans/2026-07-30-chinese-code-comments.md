# 补充中文代码注释

## 目标

让开发者不预先阅读设计文档，也能从源码理解各模块职责、主要数据流、业务约束和非直观实现。

## 背景与设计依据

项目模块数量增长后，只有类型和命名不足以解释跨层调用、安全边界、动态路由和状态同步。注释规则写入[开发工作流](../../design/developer-workflow.md)，模块组织继续遵守[模块边界](../../design/module-boundaries.md)。

## 范围

- 为契约、后端、前端和测试中的关键职责与非直观逻辑补充中文注释。
- 优先覆盖模块公共入口、HTTP 边界、服务、仓储、安全逻辑、动态路由、复杂状态和 Vue 页面主要交互链路。
- 更新现行开发工作流并记录验证结果。

## 非目标

- 不修改业务行为、API、Schema、数据库结构或页面交互。
- 不为每一行代码机械添加注释，不复述已经清晰的命名和类型。
- 不新增或运行前端自动化测试。

## 前置条件和风险

- 任务开始时暂存区和工作区均为空。
- 主要风险是注释与实现不一致；实施以当前代码、契约和测试为事实来源，并在最终差异中逐项复核。
- `pnpm format` 未产生额外格式变化。

## 实施任务

- [x] 更新中文注释规范。
- [x] 补充契约和后端关键注释。
- [x] 补充前端关键注释。
- [x] 补充测试中无法由用例名表达的意图说明。
- [x] 执行格式、静态检查、测试和构建。
- [x] 复查差异，归档计划与协作记录并创建提交。

## 测试与验证

- `pnpm format`：通过，所有文件均无需额外格式调整。
- `pnpm lint`：通过。
- `pnpm format:check`：通过。
- `pnpm test`：通过，11 个测试文件、86 个测试全部通过。
- `pnpm build`：契约、后端和前端生产构建通过。
- 人工差异检查：业务源码仅增加或替换注释，未修改运行逻辑；现行工作流、计划和协作记录按文档门禁更新。

构建仍报告 Dart Sass legacy JS API、`@vueuse/core` PURE 注释位置，以及静态/动态重复导入的既有警告；这些警告未导致构建失败，也不属于本次注释任务范围。
