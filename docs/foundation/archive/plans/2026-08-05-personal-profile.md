# Personal profile editing

## 目标

让已登录用户从头像下拉菜单进入个人资料页，自助修改姓名、邮箱和密码。

## 背景与设计依据

用户资料字段由 `users` 模块拥有，认证模块负责解析当前身份、验证密码和撤销会话。个人资料操作必须只作用于当前登录用户，不依赖 `users.manage` 权限或管理员数据范围。

## 范围

- 在共享 API 契约中定义个人资料读取、资料更新和密码更新的运行时 Schema。
- 在 users 后端模块提供受 Bearer token 保护的个人资料接口。
- 密码更新校验当前密码、散列新密码并撤销该用户所有会话。
- 在前端新增个人资料页、模块 API 和中英文文案，并从头像下拉菜单跳转。
- 补充后端路由/契约测试、模块设计与协作记录。

## 非目标

- 不修改用户名、角色、部门、账号状态或数据权限。
- 不新增头像上传、邮箱验证或忘记密码流程。
- 不新增前端自动化测试；由维护者执行浏览器人工验收。

## 前置条件和风险

- 邮箱仍受有效用户的数据库唯一约束；冲突返回既有 `RESOURCE_CONFLICT`。
- 密码变更撤销包括当前会话在内的全部会话，前端必须清理本地身份并回到登录页。
- 个人资料路由是静态受保护路由，不能依赖后端菜单配置。
