# 部门树形展示实施计划

## 目标

把部门管理从扁平列表改为能直观表达上下级关系的树表格，并让搜索和父部门选择保持一致的层级语义。

## 背景与设计依据

部门契约和数据库已经通过 `parentId`、部门闭包表达组织树，但原前端直接把扁平数组传给 `el-table`，与[部门模块设计](../../design/modules/departments.md)约定的树表格不一致。

## 范围

- 在部门模块内提供稳定的扁平记录组树能力。
- 部门管理表格使用树节点展示、展开和折叠上下级部门。
- 搜索结果保留必要的祖先路径和命中父节点的完整子树。
- 父部门字段使用树形选择，排除当前节点及其后代并禁选停用部门。
- 同步现行设计、计划、AI 协作记录和人工验收边界。

## 非目标

- 不修改部门 HTTP 契约、后端查询、数据库模型和闭包算法。
- 不新增前端自动化测试或浏览器测试。
- 不改造授权策略编辑器中的多部门选择控件。

## 前置条件和风险

- 任务开始时暂存区和工作区为空。
- 后端继续返回扁平数组，前端稳定处理多个根节点和同级排序。
- 搜索改变可见树时保留命中节点的祖先上下文。
- 前端交互行为仍需维护者人工验收，静态检查和构建不能替代浏览器验收。
