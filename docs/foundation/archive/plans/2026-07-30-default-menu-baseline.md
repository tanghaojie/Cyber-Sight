# 默认菜单迁移基线修正计划

## 目标

按照维护者确认的路由层级重写单一数据库基线中的菜单种子，移除与静态首页重复的数据，并验证根路径、布局、相对子路径及返回字段。

## 背景与设计依据

原 `0000` 基线初始化了路径为空的根目录和重复的工作台/首页菜单，导致数据库动态路由与静态首页职责重叠。菜单路径规则和最终种子以菜单、导航设计为准。

## 范围

- `0000_initial_system_schema.sql` 中 `sys_menus` 和 `sys_role_menus` 初始数据。
- 菜单路径验证、导航树 fixture 和迁移静态测试。
- 菜单、导航、数据库设计与 ADR-0026 的基线说明。

## 非目标

- 修改静态首页路由或前端布局实现。
- 为旧数据库提供数据更新或兼容迁移。
- 改变非根子菜单允许绝对路径覆盖父路径的一般能力。

## 前置条件和风险

- 维护者明确会重建数据库，因此直接修正唯一 `0000` 基线，不新增 `0001`。
- 旧数据库迁移记录与修改后的基线不兼容，禁止原地执行。

## 实施任务

- [x] 核对静态首页、路径校验、动态路由和原种子。
- [x] 更新最终设计和实施记录。
- [x] 重写默认菜单种子。
- [x] 更新并执行后端迁移/路径回归测试。
- [x] 在临时空数据库执行基线并核对七条菜单记录。
- [x] 完成文档归档、格式、lint、测试和构建。

## 测试与验证

- `pnpm format`、`pnpm lint`、`pnpm test` 和 `pnpm build` 通过；全量后端测试共 99 项通过。
- 三个定向后端测试文件共 12 项通过，覆盖路径规则、导航树和初始种子。
- Drizzle 检测到 14 张 `sys_` 表且无 Schema 漂移，没有生成后续迁移。
- 专用临时空 PostgreSQL 数据库执行单一基线成功，核对 7 条菜单、7 条角色菜单关系和 1 条迁移记录后已删除。
- 未创建或运行前端自动化测试；前端行为仍由维护者人工验收。

## 发布与回滚

新版只连接按修正后基线创建的全新数据库。回滚必须同时切回旧代码和旧数据库；不得在已执行旧版 `0000` 的数据库上复用本次文件。

## 实际偏差和遗留问题

现有路径校验实现已满足维护者确认的根节点约束，本次仅补强回归测试，没有修改运行时代码。构建保留既有 Sass legacy API 和静态/动态重复导入警告，不影响构建成功；无本次新增遗留问题。
