# 前端主题色一致性修复

## 用户目标

核查项目页面中未跟随主题颜色变化的区域，并修复为切换主题色和深色模式后仍保持一致的视觉表现。

## 实施范围

1. 审计 `apps/frontend` 的主题令牌、全局样式、布局、登录页、工作台、关于页、错误页、设置弹窗、导航和标签页。
2. 清理会覆盖主题语义的硬编码颜色；保留正常、警告、错误和加载等明确状态令牌。
3. 验证格式、类型和生产构建，并记录人工验收边界。

## 设计约束

- 不新增主题选项，不改变设置持久化结构，不改变路由和 API。
- 主题色通过 `settings.theme.ts` 与 CSS 语义令牌驱动。
- 其他模块只依赖已登记的公开主题控制入口，不跨模块读写内部状态。
- 前端不创建或运行自动化测试；人工验收由维护者完成。

## 实际改动与偏差

- 新增全局侧栏语义令牌，并让品牌 Logo、创建者署名、侧栏、遮罩和导航状态使用当前主题的前景/表面令牌。
- 将关于项目页的独立旧调色板映射到当前主题的 Hero、品牌强调、节点、文字和表面令牌；未新增主题选项。
- 清理登录装饰、首页网格、个人资料 Hero、404、权限策略编辑器和 Element Plus 消息框中的固定颜色。
- 未发现 API、数据模型、路由或主题持久化结构需要调整。
