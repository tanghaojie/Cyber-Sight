# 动态首页与根入口解析

## 目标

让首页回归数据库动态菜单和权限过滤，并为已认证用户访问 `/` 提供稳定落点，避免静态首页绕过菜单权限或空菜单导致循环跳转。

## 背景与设计依据

当前静态 `/` 直接渲染工作台，侧栏和顶部导航额外插入首页。动态菜单无法控制首页可见性；直接删除静态首页后，根路径又会落入 404。方案以[前端应用与应用壳](../../design/modules/frontend.md)、[前端导航](../../design/modules/navigation.md)、[工作台](../../design/modules/home.md)和[错误页面](../../design/modules/errors.md)为依据。

## 范围

- 移除静态首页路由和导航组件中的首页特例。
- 在动态路由安装时记录根页面与首个成功注册的站内页面。
- 根入口按“静态根页面、动态根页面、首个动态页面、无权限页”解析。
- 提供已认证但没有可访问页面时的静态无权限页。
- 追加 `home.read` 权限与默认动态工作台菜单迁移，不覆盖现有工作台或根页面配置。
- 菜单刷新移除当前页面时回到新的有效落点。
- 同步设计、计划和 AI 协作记录。

## 非目标

- 不改变后端权限判断、菜单数据模型或 API 契约结构。
- 不创建或运行前端自动化或浏览器测试。
- 不把外链按钮或目录作为自动落点。

## 前置条件和风险

- 动态路由必须在解析 `/` 前完成安装。
- 根目录不是可渲染页面，不能仅因路径为 `/` 就作为落点。
- 已认证且无页面权限时不能跳登录页，否则会与登录页的已认证重定向形成循环。
- Vue Router 同路径记录不能依赖注册顺序，根页面和首个页面使用稳定路由名称跳转。

## 发布与回滚

本次包含幂等追加迁移，不修改既有迁移。代码回滚后，已执行迁移创建的 `home.read` 和动态工作台记录应保留或由维护者通过菜单与授权管理停用，不执行破坏性向下迁移。

## 实际偏差和遗留问题

代码、迁移和现行设计已经完成。完整前端构建最初被 `positions.api.ts` 对响应联合类型读取 `data` 的既有收窄错误阻塞；维护者随后明确授权修复，最终以 `'data' in result` 守卫补足类型收窄，不改变接口行为。后端 126 项测试、ESLint、Prettier、完整前端 TypeScript/生产构建和 `docs:archive:check:ci` 均通过。前端交互仍按仓库边界由维护者人工验收。
