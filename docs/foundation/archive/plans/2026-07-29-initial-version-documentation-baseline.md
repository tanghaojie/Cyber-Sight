# 初始版本文档基线整理

## 目标

以维护者截至提交 `f10f584` 的实现为初始版本事实来源，同步现行设计，建立“人类修改优先”的仓库协作原则，并把初始版本之前的重复设计和 ADR 收入历史归档。

## 背景与设计依据

维护者已完成路由结构、TypeScript 配置、空目录菜单显示和前端认证 API 分层调整。现行文档仍描述旧的页面注册文件、路由守卫位置、登录响应和 token 存储方式，需要以实现为准更新。

本计划遵循 [分层文档与历史归档](../../design/documentation-governance.md)；新的长期协作原则由 ADR-0024 记录。

## 范围

- 保留维护者业务实现，只执行维护者明确授权的仓库级格式化。
- 更新 `AGENTS.md`、文档治理、系统概览和相关模块设计。
- 把前端应用壳的现行内容合并到前端模块设计，并归档旧独立设计。
- 把初始版本之前的现行 ADR 合并为初始版本事实并归档，仅保留新的基线治理 ADR。
- 更新当前与归档索引、计划和 AI 协作记录。

## 非目标

- 不修复、重命名或重构维护者代码。
- 不改变 API、数据库、路由或界面行为。
- 不运行前端自动化或浏览器测试。

## 前置条件和风险

- 任务开始时暂存区为空，工作区在执行获准的 `pnpm format` 前为干净状态。
- 归档会改变文档路径；必须检查当前区链接和索引。
- 发现实现问题或无法确定的文档语义时，不自行改代码或猜测，记录事实并询问维护者。

## 实施任务

- [x] 审阅维护者提交及相关现行设计。
- [x] 运行获准的仓库格式化并确认源码仅有排版差异。
- [x] 加入人类修改优先原则和初始版本基线 ADR。
- [x] 同步认证、路由、菜单、注册表和工程配置文档。
- [x] 合并并归档前置设计与 ADR，更新索引。
- [x] 完成格式、链接、静态检查、构建和最终差异审阅。

## 测试与验证

- `pnpm format` 与 `pnpm format:check` 通过。
- `pnpm lint` 通过。
- `pnpm test` 通过：9 个后端测试文件、63 个测试全部通过，契约包构建和产物校验通过。
- `pnpm build` 通过：契约、后端和前端全部完成生产构建。
- 117 份 Markdown 相对链接检查通过，`git diff --check` 通过。
- 忽略空白后的源码差异检查通过，确认获准格式化没有逻辑差异。
- 未运行前端自动化或浏览器测试；前端功能与交互仍由维护者人工验收。

## 发布与回滚

文档与获准的机械格式化在同一提交交付。若需回滚，恢复该提交即可；历史文档仍保留在 `docs/archive/`。

## 实际偏差和遗留问题

- `pnpm format` 由维护者在任务中追加授权，31 个既有格式差异已统一处理。
- 前端构建仍提示 `AdminLayout.vue` 和 `HomePage.vue` 同时被静态与动态导入，影响拆包但不阻止构建；按人类修改优先原则未改实现。
- `auth.api.ts` 的 `gerCurrentUser` 命名以及 `auth.store.ts` 的存量未使用导入不影响当前 lint、测试或构建，是否清理由维护者决定。
- 文档与获准格式化随提交 `docs: establish initial version baseline` 交付。
