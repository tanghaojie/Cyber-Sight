# 健康检查模块

## 职责与边界

前端 Health 模块负责在应用壳中轮询 `GET /health`，把后端进程是否仍可响应转换为侧边栏运行状态指示。它只表达进程存活，不检查数据库或其他下游依赖，也不负责全局 HTTP 错误导航。

模块入口是 `apps/frontend/src/foundation/modules/health/composables/useHealth.ts`，由 `AppSidebar.vue` 消费。模块依赖共享 HTTP 客户端、`health` API 契约和 localization；不直接依赖后端实现。

## 状态与数据流

- 挂载时立即发起健康检查，之后每 6 秒轮询一次；卸载时清理定时器。
- `loading` 表示首次检查尚未结束，`ok` 表示收到符合契约的成功响应，`error` 表示请求失败、超时、响应解析失败或响应结构无效。
- 成功响应写入后端时间戳；失败时清除时间戳并保留可本地化的错误文案，避免继续展示上一次成功检查的时间。
- 健康探针请求在 5 秒后通过 `AbortSignal` 取消。网络断开、超时、HTTP 业务错误和无效响应都必须收敛到 `error` 状态，不能让异常离开轮询回调。

## 失败模式

健康检查失败不会清理认证会话、导航数据或动态路由；这些动作仍由共享 HTTP 错误处理器按 HTTP `401`、`404`、`500` 规则负责。Health 模块只更新自己的指示状态。

## 验证策略

AI 可执行格式检查、前端 TypeScript 检查和生产构建；这些检查不替代人工验收。维护者应人工验证：后端正常时显示 `ok`，停止或断开后端后最多约 5 秒显示错误，恢复后端后下一次轮询恢复 `ok` 并更新时间戳。
