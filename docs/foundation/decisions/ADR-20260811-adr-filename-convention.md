# ADR-20260811-adr-filename-convention：ADR 日期命名规则

## 背景

项目原先使用 `ADR-NNNN-<topic>.md`。顺序号需要多人或多个 AI 协作者共享分配，平行工作时可能在合并前产生相同编号；即使 topic 最终不同，重复的编号仍会增加阅读和沟通成本。

计划和 AI 协作记录已经使用日期命名。ADR 也可以使用创建/接受日期与主题组合，在不引入集中式编号分配的情况下提供时间线索。

## 决策驱动因素

- 支持多人和多 AI 分支并行创建 ADR。
- 保持文件名可读、可排序和可从 topic 直接检索。
- 不破坏既有 ADR 的历史路径和仓库内外引用。
- 让归档审计继续统计既有 ADR。

## 考虑的方案

1. 继续使用全局递增顺序号：现有规则简单，但需要协调编号，并发时容易重复。
2. 使用 `ADR-YYYYMMDD-<topic>.md`：日期提供时间线索，topic 负责同日唯一性，适合并行协作。
3. 在日期和 topic 外增加时间戳、短 UUID 或提交哈希：冲突概率更低，但文件名更长，降低可读性，且创建时可能尚未有提交哈希。

## 决策

从本 ADR 起，新增 ADR 使用：

```text
ADR-YYYYMMDD-<topic>.md
```

其中：

- `YYYYMMDD` 是 ADR 创建/接受日期，并且必须对应 frontmatter 的 `date: YYYY-MM-DD`。
- `<topic>` 使用简短、稳定的小写 kebab-case slug。
- 日期和 topic 在 ADR 创建后保持不变。
- 同日创建多个 ADR 时使用不同 topic，不分配顺序号。
- 既有 `ADR-NNNN-<topic>.md` 文件作为历史兼容格式保留，不重命名；既有正文标识和引用保持原样。
- 新增文档引用新的 ADR 时使用日期命名路径。
- 归档审计同时识别四位顺序号旧格式和八位日期新格式。

## 正面结果

- 并行协作者无需预先领取全局编号。
- 文件名按日期自然排序，topic 仍能表达决策主题。
- 既有 ADR 路径和外部链接不因本次规则变更失效。
- 新旧格式可以在过渡期共存，归档统计不会漏掉历史 ADR。

## 负面结果与风险

- 日期本身不能保证唯一性；topic 必须保持仓库范围内唯一，尤其是同日 ADR。
- 既有 ADR 和新 ADR 的文件名格式会在一段时间内并存。
- 外部工具若硬编码 `ADR-\d{4}`，需要同步采用新规则或兼容两种格式。

## 验证和复审条件

- ADR 模板、文档入口和现行索引描述新规则。
- 归档审计能够识别旧格式和新格式。
- 新增 ADR 的文件名日期与 frontmatter 日期一致。
- 若 topic 冲突频繁或日期命名无法满足外部系统集成，再评估增加短唯一后缀；在此之前不引入时间戳或 UUID。
