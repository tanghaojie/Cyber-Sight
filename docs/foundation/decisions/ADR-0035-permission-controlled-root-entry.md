# ADR-0035：权限控制的动态首页与根入口

## 背景

静态 `/` 工作台可以保证根路径始终有内容，但它绕过数据库菜单可见性，无法按用户权限隐藏首页。直接删除静态首页后，已认证用户访问 `/` 又可能进入 404；没有任何菜单的账号若被送回登录页，还会与“已登录用户离开登录页”的规则形成循环。

## 决策驱动因素

- 首页必须与其他页面使用同一套菜单权限、排序和动态路由机制。
- 根路径必须在动态路由安装完成后解析，不能把尚未安装菜单造成的临时未匹配当作 404。
- 目录、外链和无法生成路由的菜单不能成为自动落点。
- 已认证但没有页面权限与未认证是不同状态。
- 维护者已经配置的工作台路径或根页面不能被迁移覆盖。

## 考虑的方案

1. 保留静态首页并只隐藏导航项：直接访问仍可见，不能落实菜单权限。
2. 没有动态 `/` 时跳登录页：实现简单，但已认证账号会发生循环并错误表达授权状态。
3. 把 `/` 作为认证后入口解析点：首页使用动态菜单；根页面不存在时选择首个有效站内页面；没有页面时进入无权限页。

## 决策

采用方案 3：

- 默认静态路由不占用 `/`，工作台通过 `home` 页面注册表和数据库菜单生成动态路由。
- 动态路由安装记录第一个成功生成的站内页面和路径为 `/` 的页面，并使用稳定路由名称跳转，不依赖同路径记录的注册顺序。
- `/` 的优先级为：显式声明的静态根页面、当前用户可见的动态根页面、首个可见且成功注册的动态页面、静态 `/403` 无权限页。
- 默认工作台菜单绑定 `home.read`。追加迁移只在不存在有效 `home` 页面且不存在其他有效根页面时创建 `/` 工作台，并只给初始超级管理员授权。
- 侧栏和顶部导航不再额外插入首页；菜单刷新移除当前动态页面时重新执行入口解析。
- 未知的非根地址仍进入 404；未认证用户仍进入登录页。

## 正面结果

- 首页展示、路径和排序都能由菜单管理及角色权限控制。
- 新环境默认超级管理员仍有工作台，其他账号可以拥有不同首页或直接落到首个授权页面。
- 空权限账号得到稳定、可退出的无权限状态，不会产生登录循环。
- 登录成功、直接访问 `/`、关闭全部标签和菜单权限刷新共享同一落点语义。

## 负面结果与风险

- 根入口依赖菜单加载完成；导航请求失败时仍按原有错误流程中止，不能误降级为无权限。
- 多个有效菜单配置为 `/` 属于冲突配置；运行时只接受首个成功生成的根页面并记录错误，维护者仍应修复菜单数据。
- 前端没有自动化路由测试，根页面、非根回退、空权限和权限刷新需要维护者人工验收。

## 验证和复审条件

当产品需要按用户显式保存“首选首页”、允许外链作为登录落点、支持多个应用壳或引入前端路由自动化测试时复审本 ADR。
