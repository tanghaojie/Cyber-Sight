# 测试策略

## 目标

让 AI 生成业务时能够快速获得反馈，并通过自动测试限制跨模块、API 契约和数据库结构的无意变更。

## 测试分层

1. 单元测试：验证领域规则、composable 和纯函数，不访问网络或真实数据库。
2. 组件测试：使用 Vue Test Utils 验证页面状态与交互，外部依赖必须 mock。
3. 后端路由测试：使用 Fastify `inject` 验证状态码、响应、默认值和运行时 Schema 拒绝非法输入，不监听真实端口。
4. 契约测试：构建共享 Schema 包，并验证前后端消费其推导类型；检查 Swagger 暴露的操作和关键约束来自运行时路由。
5. 数据库集成测试：显式连接本地或 CI PostgreSQL，验证连接和迁移；不包含在默认快速测试中。
6. 端到端测试：未来针对关键业务流程增加，不在当前最小基线内。

## 命令约定

- `pnpm test`：运行默认快速测试。
- `pnpm test:watch`：开发时监听测试。
- `pnpm test:db`：显式运行 PostgreSQL 连接验证。
- `pnpm build`：执行生产构建和 TypeScript 检查。

## AI 约束

- 修复缺陷前先增加能复现问题的测试。
- 新 API 必须至少包含合法请求、非法请求、响应结构和前端调用类型覆盖。
- 新页面状态必须覆盖成功与失败路径。
- 测试不得依赖执行顺序、外部网络或开发者个人数据。
- 跳过测试必须在实施计划和 AI 日志中说明原因。
