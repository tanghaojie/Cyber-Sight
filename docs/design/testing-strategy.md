# 测试与验证策略

## 目标

自动化测试保护共享 HTTP 契约、后端业务边界和数据库结构；前端功能与浏览器行为由维护者
人工验收。格式、类型检查和生产构建提供静态反馈，但不代替功能测试。

## 自动化测试范围

1. 后端单元与路由测试：使用 Vitest 和 Nest 应用底层的 Fastify `inject` 验证领域规则、状态码、响应、默认值
   和运行时 Schema 拒绝非法输入，不监听真实端口。
2. 契约校验：构建共享 Schema 包，验证前后端能够消费其推导类型；Swagger 的操作和关键约束
   来自运行时路由。
3. 数据库集成验证：显式连接本地或 CI PostgreSQL，验证连接和迁移；不包含在默认快速测试中。

`apps/frontend` 不维护单元测试、组件测试或端到端自动化测试，也不提供测试脚本和测试环境。
前端交互、错误状态、桌面端与窄屏浏览器行为由维护者人工验收。

## 命令约定

- `pnpm test`：构建契约包并运行后端快速测试，不包含前端。
- `pnpm test:watch`：构建契约包后监听后端测试，不包含前端。
- `pnpm test:db`：显式运行 PostgreSQL 连接验证。
- `pnpm build`：执行生产构建和 TypeScript 检查；不是功能测试。
- `pnpm --filter @scaffold/frontend build`：只执行前端类型检查和生产构建。

## AI 约束

- AI 默认不得创建或运行前端单元、组件、端到端或浏览器测试；维护者在具体任务中明确要求
  时除外。
- 前端改动可执行格式检查、类型检查和生产构建，并明确说明功能验收仍由维护者负责。
- 后端或契约变更仍应补充与改动相称的自动化测试；测试不得依赖执行顺序、外部网络或开发者
  个人数据。
- 用户明确接管测试时，AI 不运行测试，并在实施计划和 AI 日志中记录实际验证边界。
- 检查发现人类实现存在 bug、风险或与文档含义不明确的冲突时，AI 不自行修复；应保留实现、记录证据并询问维护者下一步。

当前边界同时受根目录 `AGENTS.md` 约束；初始版本之前的验证取舍见[归档索引](../archive/README.md)。
