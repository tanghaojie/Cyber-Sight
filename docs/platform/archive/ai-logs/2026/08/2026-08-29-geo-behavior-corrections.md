# Geo 视图、地形与测量状态修复协作记录

## 用户目标和约束

用户要求修复三个 Geo 前端问题：视图面板不随真实相机和场景模式持续同步且视距上下限可冲突；地形加载失败后 UI 与 Viewer 不一致；面积单位选择无效且点位保留无意义单位控件。

## 关键问答与确认

- 任务开始时暂存区与工作区为空；
- 本次属于 Platform Geo 行为修复，需要设计、实施计划、AI 记录、归档门禁和最终提交；
- 仓库禁止创建或运行前端自动化/浏览器测试，交互行为由维护者人工验收。

## AI 的重要假设

- Cesium 相机与场景事件是面板状态的事实来源；
- 地形切换按事务处理：只有 provider 成功安装后，新地形才成为“当前场景表面”；
- “千米”用于面积时表示平方千米，换算因子为 `1_000_000`。

## 方案和执行摘要

- 订阅相机变化、移动结束和场景 morph 完成事件，统一抓取真实快照并在销毁时解除；
- 设置任一视距边界后同步夹紧另一边界；
- 异步创建地形 provider，成功写入 Viewer 后再提交快照，失败交给 controller 的统一错误状态；
- 面积按所选单位换算，点位模式不渲染单位字段。

## 验证结果

- 视图 controller 已订阅相机变化、移动结束和场景 morph 完成事件，并在幂等 `dispose()` 中解除全部订阅；
- 单独提高最小视距时会同步提高最大视距，同时设置两边界时仍保证最小值不高于最大值；
- 地形快照只在新 provider 成功写入 Viewer 后更新，失败由数据 controller 的统一错误状态反馈；
- 面积按 `m²`/`km²` 换算，点位模式隐藏单位字段；
- `pnpm format`、lint、架构检查和前端生产构建已通过；构建在沙箱内遇到 Windows esbuild 访问限制，授权环境同命令通过。

## 未决问题与下一步

维护者需人工验收拖动/缩放期间和结束后的相机数值、右上场景模式切换、不可用地形切换、面积两种单位及点位模式。仓库规则不允许以自动化浏览器测试代替该验收。
