# Geo 底图目录交互与默认加载修复

## 目标

修复 Geo 数据面板中底图/注记目录过长、不可用源原因不透明，以及本地无第三方配置时自动请求远程候选瓦片导致地图持续失败请求和卡顿的问题。

## 背景与设计依据

- `docs/platform/design/modules/geo.md` 要求地图优先、渐进披露、局部失败隔离和第三方源按运行时条件决定可用性。
- 本地人工复现发现无 `VITE_GEO_TIANDITU_TOKEN` 时，数据插件自动加载 Google 影像候选；4 秒内产生 109 个 Google 瓦片请求，其中 68 个以 `ERR_CONNECTION_CLOSED` 失败，随后仍有失败请求。
- 天地图缺少公开客户端令牌、高德源未启用 GCJ-02 坐标校正时的禁用属于保护性行为，应在 UI 中解释，而不是只表现为灰色按钮。

## 范围

- 更新底图目录为按角色分组、可筛选、局部滚动且使用 Geo 风格滚动条的面板。
- 为可用、已加载、加载中、失败和受配置限制的源提供清晰状态与原因。
- 无天地图令牌时仅使用本地 Natural Earth 默认底图，不再自动加载 Google 或其他远程候选源。
- 将影像瓦片错误同步到控制器状态，避免失败只存在于 Cesium provider 内部。
- 更新 Geo 设计、决策、AI 日志和索引。

## 非目标

- 不新增天地图令牌、代理服务或 GCJ-02 到 WGS84 的坐标转换实现。
- 不改变第三方源的许可结论，不把候选源宣称为稳定生产数据源。
- 不新增前端自动化、端到端或浏览器测试；按仓库约定由人工验收交互和地图行为。

## 前置条件和风险

- Geo 是纯前端模块，不涉及后端、契约或数据库迁移。
- 远程源仍可能在用户主动加载后失败；失败必须局部显示并允许移除，不得阻塞 Viewer。
- 设计和计划在实现完成后需要补充实际验证结果、人工验收边界和关联提交，并移入归档目录。

- [x] 修复影像管理器和控制器的异步/错误状态同步。
- [x] 移除未配置环境中的远程候选自动回退，保留显式用户加载能力。
- [x] 更新设计、ADR、索引和 AI 协作记录。
- [x] 执行格式、类型、构建、归档 CI 检查并完成人工浏览器复测。

## 测试与验证

- `pnpm format` 后执行 `pnpm format:check`。
- 执行前端 `vue-tsc`、生产构建和 `pnpm docs:archive:check:ci`。
- 本地人工验证默认底图、源筛选/滚动、禁用原因、主动加载失败反馈和面板操作不阻塞 Viewer。

## 发布与回滚

默认数据流只从未配置时的 Google 候选回退改为本地 Natural Earth；如需回滚，仅恢复数据插件的默认选择逻辑，不恢复 UI 对不可用原因的隐藏。

## 实际偏差和遗留问题

- 为让数据插件真正拥有可见的默认图层，移除了运行时重复添加 Natural Earth 的逻辑，由数据插件统一登记本地图层。
- 远程候选源仍可能在用户主动加载后因网络、CORS 或服务策略失败；当前反馈该源的 provider 错误，不做自动重试或健康探测。
- 按仓库约定未创建或运行前端自动化/浏览器测试，人工浏览器验收覆盖 1280×720、源筛选、搜索、局部滚动、默认请求和主动候选失败隔离。
