# 桀士排版独立迁移实施计划

## 目标与当前状态

在 `JLabWeChatEditor` 独立交付桀士排版，完整保留功能和界面，采用 CoAIForge 0.2.0 工具链。首开空原稿、默认配色/排版保留，不迁入旧浏览器数据。本轮仅完成设计与计划，目标工程创建、代码迁移和功能验收均未执行。

本计划在来源仓库声明 platform。开始实际迁移后，在目标 `docs/plans/active/` 建立实施接续记录，由目标单项目规范管理；本计划记录来源交接与目标证据，不形成两份独立更新的技术任务清单。目标实施以[迁移设计](../../design/apps/jlab-wechat-editor-migration.md)为依据，确认偏差后同步来源交接状态。

## 范围、前置条件与风险

包含六模块、应用入口、配置、产品文档、依赖、锁文件、模块注册、静态产物、CI 及人工验收清单。无后端、旧数据搬迁、部署发布、源应用删除或功能/UI 扩充。生产平台和域名未定，不作为本地技术交付的前置条件。

真正写入前核对目标绝对目录、仓库是否已建、远端和分支；两仓库分别检查暂存区及未提交内容，现有改动视为人类内容。检查归档状态，有同事项活动计划时接续，不能生成到非空目录或覆盖目标现有文件。确认实施授权；本轮的规划授权不推定为创建远端、推送或发布授权。

来源设计核对基线为 `64a67f2fdcec0df8b2012359237e1aa8bd813216`。工具链大版本兼容、UI 人工验收、同 origin 存储隔离和来源/目标漂移为主要风险，不通过关闭检查或清空源数据解决。

## 阶段与退出条件

### P0：设计和来源交接准备

- [x] 核对产品、UI、存储、公共模块及工程依赖。
- [x] 确认产品/目录名、功能范围、无旧数据迁移、空原稿和目标工具链。
- [x] 编写迁移设计、决策与本实施计划。
- [ ] 实施时重新核对来源 SHA，固定提取文件清单、许可证与目标位置。

退出条件：本轮文档验证通过；实际实施前目标路径和仓库状态明确，偏差有记录。

### P1：独立工程与治理初始化

- [ ] 使用 create-coaiforge@0.2.0 frontend 预设和 `--name jlab-wechat-editor` 创建目标，或审查已生成的同版工程。
- [ ] 核对实际 CLI/模板版本、快照 SHA、所选 workspace 和许可证。
- [ ] 移除目标 introduction 示例、设计与注册，准备目标产品、UI、存储及六模块设计、计划、协作记录和适用 ADR。
- [ ] 保留单项目 AGENTS、治理、hooks 与 CI；不带入来源所有权 scope、同步机制、历史或 ledger SHA。

退出条件：目标为独立 frontend workspace；无 backend/API 契约/源仓库安装依赖；目标初始文档与未来模块结构一致。

### P2：产品源码迁入与适配

- [ ] 将六模块迁入 `apps/frontend/src/modules/`，应用配置移入 `src/app.config.ts`，只修改必要路径、组装与目标配置。
- [ ] 在 `.module-boundaries.json` 登记组装点、公共文件、依赖与六份模块设计，以目标模块门禁覆盖源检查器约束。
- [ ] 迁入 Pinia、Element Plus、Markdown-it、DOMPurify 等实际依赖，核对官方兼容和 peer，登记选取范围与许可，更新目标锁文件。
- [ ] 保留入口显式 UI 注册和样式、桌面布局、受控导出及原本地持久化规则。
- [ ] 首开 Markdown 为空；历史、最近色和素材无来源数据；默认六组配色、排版和结尾启停规则保持。
- [ ] 配置独立本地 origin 与严格端口，保留相对 base，补全目标 README、开发/预览/构建命令及人工验收清单。

退出条件：源应用不变，目标功能结构完整；路径、配置与模块注册一致；没有为了迁移添加额外业务行为。

### P3：技术验证与可复现交付

- [ ] 在目标独立安装目录执行严格 peer 安装和 `pnpm install --frozen-lockfile`，确认不引用源 node_modules。
- [ ] 执行 pnpm format、format:check、lint、typecheck、build、modules:check、docs:check 和适用治理脚本测试；不执行前端自动化。
- [ ] 核对静态资源、相对 base、根路径/子路径服务方式和输出文件，供维护者人工打开验收。
- [ ] 将适用静态检查纳入目标 CI；Windows 本地与 Windows/Linux 远端结果分别记录，未执行不写通过。
- [ ] 无首提交时执行目标 bootstrap 门禁，创建真实首提交后显式登记基线并提交台账；有历史时按正常归档流程处理。
- [ ] 完成 docs:archive:check:ci、diff 与提交规范检查，默认创建技术交付提交并核验真实模型 trailer；推送另按授权。

退出条件：目标工程适用静态门禁通过、有真实提交和归档基线、依赖可冻结安装、记录验证环境与遗留问题。构建成功不等于产品功能验收。

### P4：人工功能与公众号验收

- [ ] 桌面尺寸与 125% 缩放：单层顶栏、抽屉互斥、长文滚动、比例拖拽、键盘与专注恢复。
- [ ] 空原稿、默认设置、输入/导入、IME/撤销、Markdown、章节/编号、配色 1/9 边界、局部颜色与失效标注、固定结尾。
- [ ] 刷新恢复、current 防抖、主动历史新增/查看/恢复/删除、并发暂停、损坏/未知格式、配额或权限失败及重试。
- [ ] 手机/电脑外壳、代码/表格/图片、远程图片 CORS、HTML 与纯文本复制、权限拒绝和旧快照保护。
- [ ] 真实公众号粘贴、保存重开和微信明暗阅读，记录环境、输出 profile、差异与需修复项。

退出条件：维护者逐项确认，并记录失败后的修复和复验。待验收时目标计划保留 pending_human_acceptance；不得因技术提交或历史源应用检查通过提前归档。

### P5：交接与收尾

- [ ] 更新目标设计为最终事实，附实际来源/模板/交付提交、验证、偏差与未决事项。
- [ ] 通过允许检查且人工验收完成后，归档目标计划和协作记录，更新目标索引与真实归档基线。
- [ ] 在来源记录目标实际路径、仓库链接和迁移状态，完成本计划的来源交接并归档。
- [ ] 保留源应用；如需删除、停止维护或切换生产入口，单列任务并取得明确授权。

退出条件：目标代码、模块、产品设计、计划、日志与验收一致，来源可追溯；“可部署”与“已正式发布”明确区分。

## 发布与回滚

本阶段交付静态 dist 和部署说明，不操作未知平台。正式发布前另行确认域名、HTTPS、base、缓存策略和发布授权。开发/预览先用独立端口，不清除旧 origin 数据。切换前源应用保留；失败回到旧入口，源/目标新数据无法自动合并，不能承诺跨站数据回滚。

## 实际结果、偏差与遗留

2026-10-08 本轮仅编制文档，未执行 P1 至 P5。CodeGraph 定位返回无可用索引，已回退定向源码读取，未创建索引。任务前归档审计因 sandbox 的 workspace realpath EPERM 首次失败，在正常环境重跑通过，Platform 为 NOT_DUE。文档最终验证和本轮提交见 Platform 归档索引中的规划协作记录；不得将这些检查记为迁移或浏览器验收。

目标绝对路径、远端地址与分支在实施前核对；正式发布平台和域名在部署前确认。不要求先解决正式发布地址才能开始本地迁移。
