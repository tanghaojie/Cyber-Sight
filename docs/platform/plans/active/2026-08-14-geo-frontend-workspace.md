# Geo 前端工作台实施计划

## 目标

在 Cyber-Sight 中交付一个现代化、地图优先的纯前端 Geo 页面，以新的插件和交互生命周期架构迁移 `vue3-cesium-typescript-start-up-template` 中仍有价值的通用能力。

本计划以 [Geo 前端空间可视化工作台](../../design/modules/geo.md) 和 [Geo 前端编译期插件架构](../../decisions/ADR-20260814-geo-frontend-plugin-architecture.md) 为依据。

## 范围

- `apps/frontend/src/platform/modules/geo/` 中的页面、路由、状态、Cesium 适配器、插件和组件；
- Platform 首页到 `/geo` 的静态前端入口；
- 地图全屏布局和现代化工作台 UI；
- 旧项目通用视图、数据、环境、标绘、测量、模型与地形分析能力的迁移；
- 前端静态验证与维护者人工浏览器验收。

## 非目标

- 后端、API 契约、数据库、场景保存、用户或管理功能；
- Geo 专属功能权限、数据权限和数据库菜单；
- 用户侧 AI、模型提供商、提示词和自然语言地图操作；
- 远程插件、插件市场和用户上传代码；
- 旧项目行业大屏等特定应用；
- 前端自动化、端到端或浏览器测试。

## 实施原则

- 先交付可用工作台骨架和正确生命周期，再逐组迁移能力；
- 每个阶段形成可人工验收的页面，不一次性复制旧项目；
- 旧功能先核对依赖、数据许可和清理行为，再决定复用算法或重写；
- 新增目录和公共端口以当前真实消费者为准，不预建空架构；
- UI 以任务流和上下文组织，功能迁移不等于复刻旧 Ribbon。

## 阶段 1：路由、Viewer 与页面骨架

- [ ] 确认当前 Vite、Vue、TypeScript、Node 和浏览器基线兼容的稳定 Cesium 版本并锁定依赖；
- [ ] 配置开发与生产环境所需的 Cesium Worker、Widget、字体和 Asset 路径；
- [ ] 新建 `platform/modules/geo/`，登记 `geo.routes.ts` 和 `geo.plugins.ts`；
- [ ] 由 Platform 组合入口注册静态 `/geo` 路由，不依赖数据库菜单；
- [ ] 在 Platform 首页增加 Geo 产品入口；
- [ ] 实现幂等 `ViewerAdapter` 和页面进入/离开清理；
- [ ] 实现 Geo 工作台基础布局、WebGL 不可用、初始化中、失败与重试状态；
- [ ] 确认不新增后端、契约、migration 或权限定义。

完成条件：从 Platform 首页可进入和离开 Geo；开发与生产构建均可创建 Viewer；重复进入页面不会创建残留实例。

## 阶段 2：UI 系统与插件内核

- [ ] 实现 48–56px 顶栏、左侧工具轨、按需上下文面板、右侧属性检查器和底部状态条；
- [ ] 使用现有 Sight 设计令牌、Element Plus、图标和本地化能力；
- [ ] 定义最小插件贡献类型、`GeoContext`、注册表和错误隔离；
- [ ] 实现 `InteractionManager`，保证鼠标主交互工具互斥；
- [ ] 统一插件的激活、停用、取消和幂等销毁协议；
- [ ] 完成桌面、窄桌面和手机基础降级布局；
- [ ] 为图标按钮、焦点、活动状态、工具提示和 reduced motion 补齐无障碍行为；
- [ ] 对 1280×720 进行重点人工视觉验收，确保地图面积和信息层级明显优于旧站。

完成条件：插件可贡献工具与面板；切换任务组不重建 Viewer；活动工具和下一步操作清晰；页面不出现旧式 Ribbon 和永久宽侧栏。

## 阶段 3：视图、数据与场景能力

- [ ] 迁移全球/中国定位、相机坐标、鼠标坐标、相机高度和 FPS/状态信息；
- [ ] 实现 2D、3D、哥伦布模式、相机设置和视距限制；
- [ ] 建立影像、地形、模型和 3D Tiles 的前端预置配置；
- [ ] 实现预置数据的显示、隐藏、定位、排序或适用的局部属性调整；
- [ ] 迁移太阳、月亮、大气、光照、天空盒、阴影、地球底色和深度检测；
- [ ] 验证数据许可、浏览器令牌、CORS 和生产可用性，不提交维护者私有凭据；
- [ ] 让单数据源失败保持局部，不影响 Viewer 和其他数据。

完成条件：用户能通过任务面板完成基础浏览、数据切换和环境调整；预置数据在生产构建中可用或明确显示不可用原因。

## 阶段 4：标绘、测量与三维模型工具

- [ ] 迁移点、线、面标绘以及当前/全部结果清理；
- [ ] 迁移点位、距离和面积测量以及结果清理；
- [ ] 迁移 3D Tiles 高亮、滑动/点击分类；
- [ ] 迁移模型切割或分屏、偏移校正；
- [ ] 为每个交互工具实现取消、完成、错误和切换清理；
- [ ] 验证连续切换、重复激活和离开路由不会累积事件、实体或 Primitive；
- [ ] 在状态条或浮动提示中显示当前工具、操作步骤和退出方式。

完成条件：绘制、测量和模型工具可直接供用户使用；任意时刻只有一个鼠标主交互工具；工具退出不污染其他图层和插件。

## 阶段 5：地形分析、对比与功能收口

- [ ] 迁移地形采样、淹没分析、等高线和地形着色；
- [ ] 迁移影像或场景分屏对比；
- [ ] 为耗时分析限制输入规模、提供进度/取消反馈并保持界面可响应；
- [ ] 建立旧站通用能力对照表，记录已迁移、替代、推迟和废弃原因；
- [ ] 统一所有任务组的名称、图标、面板密度、空状态和错误提示；
- [ ] 完成 1280×720、常用桌面宽度和窄屏降级的人工视觉与交互验收；
- [ ] 完成长时间操作、连续进入/退出和外部数据失败的人工资源生命周期验收。

完成条件：设计列出的通用旧能力均有明确结论；已实现功能在统一工作台中可用；视觉和交互不再继承旧站主要问题。

## 阶段 6：最终验证与文档归档

- [ ] 更新 Geo 设计和 ADR，使其描述最终实现和实际公共接口；
- [ ] 记录 Cesium 版本、数据源、许可、运行时配置和人工验收结果；
- [ ] 运行适用的格式、类型、lint、构建、架构和文档门禁；
- [ ] 明确前端静态检查不能替代维护者人工功能验收；
- [ ] 更新计划和 AI 日志的实际偏差、验证结果、遗留问题和关联提交；
- [ ] 将完成计划和 AI 日志归档并更新索引；
- [ ] 创建并验证带真实 AI 模型 trailer 的提交。

## 验证命令

每阶段执行与改动相称的局部检查，最终至少执行：

```text
pnpm format
pnpm format:check
pnpm lint
pnpm build
pnpm architecture:check
pnpm docs:archive:check:ci
```

按仓库规则不创建或运行前端自动化、端到端和浏览器测试。人工验收以设计文档中的清单和各阶段完成条件为准。

## 风险与控制

- Cesium 资源路径在开发和生产环境不一致：阶段 1 同时验证两种构建，不延后到功能迁移结束；
- 旧算法依赖全局状态：逐个能力解耦，通过 Viewer 适配器和插件上下文接入；
- 事件和临时资源泄漏：以插件拥有权、互斥工具和幂等销毁作为完成门槛；
- 外部数据受 CORS、令牌、限频和许可影响：只发布明确允许且可被浏览器安全访问的数据；
- 为插件化创建过度抽象：只实现当前任务组共同需要的最小端口；
- UI 再次被功能数量淹没：首层按用户任务分组，高级参数按需展开，并以 1280×720 人工验收作为门槛。

## 实际偏差与遗留问题

当前尚未实施代码。Cesium 具体版本、首批预置数据和每项旧算法的复用程度在对应阶段通过兼容性、许可和源码核对确定，不改变纯前端、单页和无用户侧 AI 的范围。
