# ADR-20261007-independent-ai-collaboration-starter：采用无业务预设的独立 AI 协作启动模板

## 背景与驱动因素

维护者计划将 Cyber-Sight 的开发经验整理成可由 CLI 创建的独立项目模板，重点是人与 AI 的协作标准及 docs 设计体系。原提案包含完整管理基础、Foundation/Platform 分层及 Forge 上游关系；维护者随后明确排除这些内容，并通过交互问答确认本决策。

## 考虑的方案

| 方案                                  | 取舍                                                |
| ------------------------------------- | --------------------------------------------------- |
| 原管理系统作为模板，继续上游同步      | 带入未请求的业务、所有权和共同 Git 历史要求，不采用 |
| 精简协作规范，只复制空工程            | 不能保留严格设计、归档、提交与验收经验，不采用      |
| 独立协作标准 + 前端/后端/全栈最小工程 | 满足已确认目标，采用                                |

## 决策

1. 模板由新项目独立维护，不存在 Forge、Foundation、Platform scope 或上游继承身份。源码按模块组织，文档使用一套 design、decisions、plans、ai-logs、archive。
2. CLI 交互选择前端、后端或全选。单选为空启动工程；全栈仅包含 health、共享 Zod 契约和前端最小状态展示，不预置认证、管理功能或数据库。
3. 前端采用 Vue 3/Vite/TypeScript，后端采用 NestJS/Fastify/TypeScript；生成项目统一使用 pnpm workspace，具体版本经验证后固定。
4. 保留严格文档门禁、人类修改优先、暂存区硬门禁、最小阅读、模块公共边界和文档生命周期。非简单改动先设计、计划和 AI 日志，长期决定写 ADR。
5. 通过适用验证后默认自动提交，用户明确暂不提交时除外。保留提交分类与真实 AI 模型 trailer；无法确认模型或改动归属时停止提交。
6. AI 可执行前端静态检查与构建；前端功能人工验收，除非维护者明确要求，否则不创建或运行前端自动化测试。后端、契约和治理脚本保持适用自动化验证。
7. 自动归档审计改为单项目模式，保留条件触发、复核证据和 CI 门禁，去掉所有权分类与上游同步依赖。
8. RTK、CodeGraph 为可选增强，有工具及索引时使用，缺失时走标准命令，不自动安装或建立索引。
9. 2026-10-07 维护者进一步确认：目标仓库 CoAIForge 已创建，采用 MIT；模板采用公共基础、前端/后端片段与全栈 health 补充组合，公共规范保持单一来源。
10. 单项目审计沿用 20 有效提交、3 新 ADR、3 完成计划或 30 天触发及即时触发规则。CLI 默认只初始化 Git，不自动首提交；首个真实提交后显式登记基线，不影响 AI 开发验证后的默认提交规则。

## 影响与风险

优点是新项目只承担已选择的运行环境，并能直接使用已实践的协作规则。代价是归档审计、模块检查、health 依赖和工程配置需要提炼改写，不能直接拷贝管理系统目录。三种输出都需要独立验证。

生成项目没有来源历史，不采用 Forge Git 合并同步；未来升级机制需另行设计。严格文档与提交协议会产生维护成本，这是维护者明确选择。新项目归档首基线必须来自真实提交，不能挪用来源 ledger。

## 验证与复审条件

P0 验证设计、来源清单和计划一致；P1 验证三套最小工程、治理脚本和实际契约链路。新增框架、预置业务、改变文档门禁/前端测试边界或引入升级机制时，重新评审本 ADR，不以实施便利擅自扩展。

## 适用边界与关联

本 ADR 接受的是独立模板目标。2026-10-07 已在 CoAIForge 按本决策完成 P1 技术实施并推送 master，提交 6ae8374、bb67bd9 的三种独立工程及 Windows/Linux CI 已通过；前端人工验收已由维护者确认通过，CLI/npm 和产品迁移未启动。保存在 Cyber-Sight 的文件仍按当前规则声明 platform；不废弃当前仓库的下游身份 ADR，也不改变现有源码目录、Foundation 文档或同步协议。
