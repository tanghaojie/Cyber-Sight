# ADR-20261017：建筑静态成品与分件动画制作契约

## 背景与驱动因素

维护者要求把建筑从无到有、构件逐步飞入拼装的目标补入 Cyber-Sight 规范并写入 AIModels，供后续建模。当前有 DEV 固定样例预览和静态模型目录，不能把引擎动画支持等同于目录中的通用动画工作流。

## 考虑的方案

1. 合并全楼，仅制作 Blender 可见性/材质特效：不足以支持可交换的逐件飞入。
2. 在同一 GLB 混放成品、拼装、爆炸动画并自动播放全部：可能覆盖同一节点，也无法保证静态默认完整。
3. 静态成品与单目的动画分别导出，源工程保留语义部件及装配矩阵：采用。

## 决策

采用 CS-AM-1 制作约定：新建筑默认提供静态成品、飞入拼装和爆炸分解，明确仅静态委托可声明不适用。分件保留稳定 ID、节点关系、枢轴和原始装配 TRS；GEO_ROOT 与全楼地理锚点固定。动画使用核心节点 TRS、共同局部时间原点与可随机采样的确定性曲线，复杂生成工具先烘焙。

材质、UV、静态窗灯、WGS84、轴向和渲染沿用现行主规范。Blender 预览灯光不随资产导出，不依赖 DEV 改色或柔光补偿修复新资产。静态成品仍为发布 v1 的主模型；部件清单和动画说明是制作附录，不扩展现行资源类型、质量版本语义或加载器。

Cyber-Sight 维护消费约束及验收契约，AIModels 保存完整制作执行版和逐建筑任务书。双方以相同标准编号和修订日期关联；需求变化时同时复核，不修改历史模型或历史验收记录来伪装已符合新标准。

## 结果、风险与复审

成品与动画分别优化、检查和验收，代价是更多导出文件及版本一致性核对。细粒度分件增加 draw call、通道和 CPU 成本，应按逻辑组控制并实际测量。本文确认制作契约，不代表已制作或视觉验收新资产。

未来目录发现动画、统一控制面板、材质动画扩展或脚本自动解析附录时，需另开协议和运行时设计，并重新评估时间、清理、兼容及人工验收。
