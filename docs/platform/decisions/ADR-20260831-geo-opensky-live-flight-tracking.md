# ADR-20260831：Geo OpenSky 实时航班数据边界

## 背景

Geo 需要为个人研究提供可开关的实时航班展示。OpenSky 匿名接口能提供最新状态向量，但不提供完整商业航班计划；实际响应头也不允许 Cyber-Sight 浏览器跨域直连。Geo 已有唯一 `viewer.clock` 仿真时间源，而实时网络快照使用墙钟时间。

## 决策驱动因素

- 不把匿名研究接口描述为可靠商用航班服务；
- 避免浏览器 CORS 失败和客户端凭据暴露；
- 只在用户明确开启后消耗匿名额度；
- 保持插件资源、失败和仿真时间边界清晰；
- 控制实时目标数量与 Cesium 渲染成本。

## 考虑的方案

1. 浏览器直接调用 OpenSky：代码最少，但真实响应头会阻止跨域请求。
2. 在 Vite 开发服务器配置代理：只解决本地开发，生产部署不可用。
3. 增加 Platform `geo` 后端薄代理：能统一输入/输出契约、超时、上游错误和生产路径，不保存数据或凭据。

## 决策

采用方案 3：

- 共享契约定义视域边界和规范化航空器状态；后端 `geo` 模块验证查询、调用匿名 `/states/all`、校验上游响应并返回统一业务包装；
- 路由要求已认证用户，OpenSky 限频、超时、网络或响应异常返回既有 `EXTERNAL_DEPENDENCY_ERROR`，不得伪装成成功空列表；
- 前端 Flight 插件默认关闭，只在开启后按当前视域每 30 秒轮询并允许手动刷新；关闭或销毁时中止请求并清空本次会话资源；
- 轨迹是开启后累积的有限样本窗口，不调用实验性 `/tracks`，不声称是完整起降航线；
- OpenSky 快照使用真实墙钟时间并以常量位置更新 Cesium 实体，不创建或修改第二个 Clock，也不改变现有 `viewer.clock`；未来历史回放必须复审时间范围；
- 全球级超大视域不发请求，单次渲染航空器数量和每架轨迹点数设置明确上限；
- 数据只在内存中存在，不持久化、不转售、不提供管理后台。

## 正面结果

- 本地和生产使用同一 API 路径，避免 CORS 假通过；
- OpenSky 失败局部隔离，不影响 Viewer 与其他插件；
- 默认关闭与视域查询降低匿名额度和渲染成本；
- 实时墙钟和仿真时间语义不混淆。

## 负面结果与风险

- 后端新增一个外部网络依赖；
- 匿名额度按来源 IP 汇总，多个用户共享部署出口时更容易限频；
- OpenSky 覆盖、呼号和高度字段可能缺失，短轨迹也会因轮询与接收覆盖出现断点；
- 当前方案不支持历史回放、起降机场、延误和完整航线。

## 验证和复审条件

- 真实前后端联调必须证明 OpenSky 数据能经本地 `/api` 代理进入页面；
- 开启、关闭、页面离开、空结果、超大视域、断网和 `429` 必须有明确状态且无资源残留；
- 若接入 OpenSky OAuth、历史 Track、其他供应商、持久化、公开部署或仿真回放，复审本 ADR 和仿真时间 ADR。
