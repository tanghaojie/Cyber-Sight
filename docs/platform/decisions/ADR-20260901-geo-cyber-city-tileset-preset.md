# ADR-20260901：Geo 赛博城市 3D Tiles 启动预置

## 背景

Geo 数据插件已经支持浏览器会话内加载 glTF/GLB 和 3D Tiles，但进入工作台后没有默认三维建筑，外部模型输入也为空。维护者希望使用指定成都建筑白模作为启动内容，并认为原生 `Cesium3DTileStyle` 的分级着色缺少视觉表现力。

该白模的 b3dm 内容提供位置、法线、批次和高度等数据，能够在 Cesium 1.144 的 `CustomShader` 中生成材质细节。Geo 既有设计只允许太阳光照和太阳阴影，不增加月光、人工场景光源或天气模拟；既有性能证据也要求避免默认启用额外全屏后处理。

## 决策驱动因素

- 启动后直接看到可交互的三维建筑，不要求用户先填写 URL；
- 形成与 Cyber-Sight 深色工作台一致、明显区别于专题分级图的城市视觉；
- 保留太阳光照和模型工具，不新增场景人工光源；
- 高空总览时减少不必要的建筑绘制和视觉噪声；
- 远程资源和实验 Shader 失败不能阻塞 Viewer、影像或其他插件；
- Shader、监听器和 Tileset 必须随 Data 插件会话释放。

## 考虑的方案

### Cesium3DTileStyle 高度分级

实现简单且可使用现有 `height` 属性，但视觉接近专题统计图，无法提供窗格、轮廓辉光和扫描带；不满足维护者确认的视觉方向。

### 影像覆盖或外部立面纹理

可增加真实感，但需要匹配授权、坐标和立面纹理，墙面容易拉伸；Cesium Tileset 影像覆盖仍是实验能力，不作为默认依赖。

### CustomShader 程序化赛博材质

用位置和法线生成深蓝渐变、窗格、屋顶分层、视角轮廓和扫描带；只修改模型材质，不创建照亮周边的人工光源。该方案由维护者确认。

## 决策

1. Data 插件启动时异步加载 `https://sample-data-jt.vercel.app/cd-buildings/3dtile/tileset.json`，成功后自动定位；加载失败只写入 Data controller 的局部错误状态。
2. 启动预置使用独立纯 Cesium 工具创建 `CustomShader`，采用深蓝楼体、青色窗格与轮廓、紫色高层点缀和扫描带；不同时设置 `Cesium3DTileStyle`。
3. 扫描相位只在唯一 `viewer.clock` 播放时推进；暂停后冻结，并沿用现有按需渲染，不创建独立动画循环或第二个 Clock。
4. Shader 只产生材质自发光，不增加人工场景光源或全屏 Bloom；原有太阳光照、太阳阴影和模型工具继续工作。
5. 启动预置保留“科技扫描 / 原始材质”切换；用户手工加载的第三方 Tileset 默认保持原始材质。
6. 当相机椭球高严格大于 `30,000` 米时，启动预置自动隐藏；回到不高于阈值时恢复到用户此前选择的显示状态。UI 的显示复选框表达用户意图，并单独说明高空自动隐藏状态。
7. Data 纯工具拥有 Shader、相机/场景监听器和 Tileset 的清理责任；移除资源或销毁插件时取消引用并销毁 GPU 资源。

## 正面结果

- 首屏形成明确、可识别的三维城市演示内容；
- 程序化图案不增加纹理网络请求，且能利用现有位置和法线；
- 30 km 自动隐藏降低高空总览中的绘制负担和遮挡；
- 预置行为与第三方手动加载行为分离，避免对未知数据强行套用样式。

## 负面结果与风险

- `CustomShader` 在 Cesium 1.144 中仍是实验能力，真实 GPU 编译与不同浏览器表现必须人工验收；
- 位置驱动的窗格是视觉化表达，不代表真实建筑立面或灯光数据；
- Shader 增加片元计算，高分辨率、集成显卡和大量可见建筑下仍需观察 FPS；
- 静态检查和生产构建不能证明 Shader、远程 CORS、自动定位或 30 km 阈值切换的实际效果。

## 验证和复审条件

- 静态执行格式、TypeScript、lint、架构、生产构建和文档归档门禁；
- 维护者人工检查默认加载、自动定位、原始/科技切换、模型工具、时间播放/暂停、30 km 上下阈值和页面离开清理；
- 若 Cesium 升级导致 CustomShader 输入、材质管线或销毁语义变化，复审本决策；
- 若真实 GPU 测量显示明显回归，优先减弱窗格/轮廓计算或默认回到原始材质，不引入全屏 Bloom 补偿。
