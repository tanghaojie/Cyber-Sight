# ADR-0017：数据库菜单选择受控布局并按目录继承

## 背景

动态菜单页面当前全部固定挂在 `AdminLayout` 下，无法让不同目录或页面选择应用壳。直接把数据库布局字符串拼接成任意动态 import 会破坏 Vite 静态分析和现有受控页面加载边界。

## 决策

菜单数据增加稳定 `layout` 标识。前端在构建期通过 `import.meta.glob` 发现 `src/layouts/*.vue`，以文件名（不含扩展名）建立只读布局注册表，并把同一注册表的键提供给菜单管理表单。

动态路由递归解析路径和布局：节点非空 `layout` 覆盖继承值，空值继承最近目录布局，仍为空时回退 `AdminLayout`；相对路径拼接最近目录路径，绝对路径覆盖上级前缀。目录自身不生成可访问路由，只向后代传递路径与布局上下文；菜单生成“布局父路由 + 页面默认子路由”。未知显式布局、未知页面组件或无法解析的路径均不注册路由，禁止回退为任意源码路径。

按钮不承载站内页面，`layout` 必须为空。数据库迁移为存量记录增加默认空值，因此旧菜单保持 `AdminLayout` 行为。

## 结果与风险

- 新布局只需新增顶层 `.vue` 文件即可进入选择项，同时仍属于构建期白名单。
- 目录可以统一指定后代布局，菜单可以按需覆盖。
- 重命名布局文件会使仍引用旧标识的菜单失效；管理页仍应展示旧值供修正，执行路由不得猜测替换。
- 布局必须提供 `<RouterView>`（或等价出口）才能显示菜单页面，该约束由维护者人工验收。

## 验证和复审条件

- 维护者人工验收布局文件发现、目录继承、菜单覆盖、默认回退和未知布局拒绝。
- 共享契约、后端菜单映射、前端类型检查与生产构建通过；后端相关自动化测试保持通过。
- 若未来支持嵌套路径目录或远程布局，再重新评估路由树形态和信任边界。
