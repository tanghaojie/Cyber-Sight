# ADR-0013：以表意公共文件替代模块 `index.ts`

## 背景

ADR-0009 使用模块级 `index.ts` 建立单一公共入口，能够阻止调用方穿透模块边界，但文件名无法说明实际依赖的是路由、状态、API 还是用例。随着模块能力增加，`index.ts` 容易退化为转发大量内部符号的 barrel，使搜索结果、依赖审查和重构影响面不够直观。

仓库代码规范要求尽量避免 `index.ts`，让文件名直接表达职责。本决策保留独立模块目录和显式公共边界，同时调整公共能力的命名与登记方式。

## 决策驱动因素

- 导入语句应直接显示依赖的职责。
- 公共边界仍需可登记、可审查，不能以删除 barrel 为由允许任意深层导入。
- 页面注册、路由、状态和 API 等不同能力应能独立演进。
- 存量模块需要渐进迁移，避免一次性修改所有 workspace。

## 考虑的方案

1. 保留每个模块的 `index.ts`。边界集中，但名称不表意且容易膨胀。
2. 把 `index.ts` 机械重命名为 `public-api.ts`。名称略有改善，但仍保留无差别转发层，依赖职责仍不明确。
3. 由模块设计登记一个或多个表意公共文件，调用方直接依赖承担职责的文件；删除无工具约束的模块级 `index.ts`。

## 决策

采用方案 3。

模块公共能力使用 `<module>.routes.ts`、`<module>.store.ts`、`<module>.api.ts`、`<module>.schema.ts`、`view-registry.ts` 或更具体的用例文件名。模块设计文档登记允许跨边界使用的公共文件和符号；未登记文件仍是内部实现，禁止其他模块导入。

不创建仅用于转发其他文件的模块级 `index.ts` 或同类 barrel。只有包发布入口、框架固定约定或第三方工具限制无法替代时才允许保留，并在设计文档说明原因。应用组合根可以直接依赖已登记的路由、store 或注册文件。

本次先迁移 `apps/frontend/src/modules` 下全部存量 `index.ts`。后端与 API 契约的存量入口在所属模块实质修改时按同一规则迁移。

## 正面结果

- 导入路径直接说明调用方依赖的能力。
- 删除无业务语义的转发层，搜索和重构更直接。
- 一个模块可以按职责公开多个小而稳定的边界，不必持续扩大单一 barrel。
- 保留公共文件登记机制，模块边界不会退化为任意深层导入。

## 负面结果与风险

- 调用方需要知道目标能力对应的公共文件名。
- 若模块设计未及时登记公共文件，可能误把内部文件当成公共接口。
- 存量迁移期会同时存在 `index.ts` 与表意入口，需在模块被触及时持续清理。

## 验证和复审条件

- 搜索 `apps/frontend/src/modules/**/index.ts` 应无结果。
- 搜索前端导入路径，确认调用方只引用设计登记的表意公共文件。
- 前端类型检查、Vitest 和 Vite 生产构建必须通过。
- 若公共文件数量失控或调用方频繁依赖实现细节，复审登记粒度和模块职责，而不是恢复无差别 barrel。
