# ADR-0012：模块页面自动注册与 SCSS 分层

## 背景

动态菜单页面虽然由受控注册表加载，但每增加一个模块都要修改中心 `view-registry.ts`，使组合根持续感知所有业务模块。与此同时，Element Plus 主题变量、各组件覆盖、布局和页面公共样式集中在 `main.css`，文件职责和覆盖顺序逐渐难以辨认。

## 决策驱动因素

- 新模块应能在自己的目录中声明页面入口，不要求修改中心业务清单。
- 数据库组件标识仍必须映射到构建期源码白名单，不能退化为任意路径动态加载。
- 重复标识和错误注册文件必须尽早失败，不能依赖对象属性覆盖顺序。
- 全局样式需要清晰的所有权、稳定的加载顺序和可读的嵌套结构。

## 考虑的方案

1. 保留中心手工注册表。实现直接，但组合根会随模块数量持续修改。
2. 根据数据库字符串拼接页面文件路径。省去声明文件，但破坏 Vite 静态分析、安全白名单和模块边界。
3. 用 `import.meta.glob` 在构建期发现约定命名的模块注册文件，每个文件通过统一 registrar 显式登记页面；样式使用 SCSS 入口并按职责和 Element Plus 组件拆分。

## 决策

采用方案 3。需要参与数据库动态菜单的模块创建 `src/modules/**/view-registry.ts` 并导出 `registerViews(registrar)`。路由组合根按稳定路径顺序调用所有注册函数，拒绝空白名称、重复名称和缺少规定导出的文件，最终冻结普通对象供动态路由只读查询。

自动发现只扫描确定的源码约定，不读取数据库文件路径、不扫描任意 Vue 文件，也不提供运行时模块上传。模块注册文件是路由组合根专用的集成清单，不作为业务模块间的第二个通用导入入口。

全局样式改用 SCSS。`main.scss` 只声明组合顺序；项目令牌与 reset、过渡、管理页面公共样式和侧栏样式分别维护。Element Plus 全局 CSS 变量单独维护，各 `el-*` 组件覆盖各自维护，避免不同组件规则互相掩盖。

## 正面结果

- 新动态页面只需修改所属模块，中心注册表无需追加 import 和对象属性。
- 仍保留可审查、可测试、构建期确定的页面白名单。
- 注册冲突在启动或构建阶段显式暴露。
- 第三方组件覆盖的职责与加载顺序清晰，SCSS 嵌套提升可读性。

## 负面结果与风险

- `import.meta.glob` 绑定 Vite 构建能力；迁移构建器时需要提供等价的构建期发现机制。
- 模块注册文件属于命名约定，拼写错误会使页面未被发现；维护者需人工校验预期内置组件存在。
- SCSS 增加一个前端构建依赖，并需要避免过深嵌套或无意义拆分。

## 验证和复审条件

- 前端类型检查和 Vite 生产构建必须通过。
- 维护者人工验收内置模块发现、重复名称与非法注册拒绝、未知数据库组件不生成路由，以及
  侧栏对比度、Element Plus 主按钮和表单/表格覆盖。
- 若未来不再使用 Vite，或需要远程模块联邦，重新评估发现机制但仍保留显式信任边界。
