# ADR-0022：前端验证由维护者人工负责

## 背景

`apps/frontend` 原有 14 个 Vitest 单元或组件测试文件，并为此维护 Vue Test Utils、jsdom、
Vitest 配置和独立测试脚本。维护者认为这些测试对当前管理端脚手架的实际收益有限，前端功能
和浏览器行为更适合由维护者结合真实使用场景验收。

## 决策驱动因素

- 降低前端测试桩、DOM 模拟环境和构建插件重复配置的维护成本。
- 让前端验收责任与维护者的实际工作方式一致。
- 避免 AI 为满足形式化覆盖率而继续生成低价值前端测试。
- 保留 TypeScript 和生产构建对静态错误、模块解析及资源打包的反馈。

## 考虑的方案

1. 保留全部前端测试。自动回归能力最强，但继续承担当前维护成本。
2. 只保留纯函数测试。成本较低，但仍需维护 Vitest 依赖、配置和脚本。
3. 移除前端自动化测试，由维护者负责功能与浏览器验收，AI 只执行非测试的静态检查和构建。

## 决策

采用方案 3。删除 `apps/frontend` 中全部 `*.test.*`、Vitest 配置、前端测试脚本，以及仅供
测试使用的 Vitest、Vue Test Utils 和 jsdom 依赖。根目录 `pnpm test` 与 `pnpm test:watch`
不再包含前端。

前端功能、交互、桌面端和窄屏浏览器行为由维护者人工验收。AI 默认不得创建或运行前端
单元测试、组件测试、端到端测试或浏览器测试；只有维护者在具体任务中重新明确要求时才能
执行。AI 仍可运行 Prettier、TypeScript 检查和 Vite 生产构建，因为这些属于静态与构建
验证，不代替人工功能验收。

后端 Fastify 测试、共享契约构建校验和显式数据库验证不受本决策影响。

## 正面结果

- 前端依赖、配置和日常命令更精简。
- AI 与维护者对前端验收责任的边界明确。
- 不再为 DOM mock 和测试运行环境维护与生产无关的适配代码。

## 负面结果与风险

- 前端纯函数、路由、store 和组件回归不再由自动化测试及时发现。
- 人工浏览器验收不可重复，覆盖范围取决于维护者实际执行的场景。
- 大规模前端重构只能依赖类型检查、生产构建、代码审查和人工验收共同降低风险。

## 验证和复审条件

- `apps/frontend` 不存在 `*.test.*`、Vitest 配置、前端测试脚本或专用测试依赖。
- 根目录测试脚本不再调度前端测试，前端生产构建仍可独立执行。
- 本次迁移只检查文件清单、格式和前端构建，不运行任何测试或浏览器。
- 若前端复杂度、团队规模或发布频率上升，或者人工验收持续遗漏高影响回归，应复审是否恢复
  有针对性的自动化测试，而不是默认恢复全部旧测试。
