# ADR-0004：HTTP 状态与前端全局错误处理边界

> ADR-0011 取代本决策中通过浏览器 DOM 事件发布错误的具体机制；401/404/500 的全局处理边界继续有效。

> ADR-0006 仅取代本决策中手写 OpenAPI 响应声明的实现方式。HTTP 状态与前端处理边界继续有效，当前由共享运行时 Schema 和 Fastify 生成文档表达。

## 背景

前端需要把登录失效、页面或资源不存在、服务端内部异常作为应用级问题统一处理；参数、权限、冲突、限流和外部依赖等错误则需要业务模块结合当前操作给出反馈。如果全部依赖不同 HTTP 状态，模块与全局处理容易重复或互相覆盖。

## 决策

- 未认证返回 HTTP `401`，响应体业务码为 `1001`。
- 资源或路由不存在返回 HTTP `404`，响应体业务码为 `1003`。
- 未分类内部异常返回 HTTP `500`，响应体业务码为 `9000`。
- 其余错误均返回 HTTP `200`，通过非零 `status` 区分参数错误、权限不足、资源冲突、限流和外部依赖等原因。
- 前端共享 API Client 的响应拦截器只统一处理 HTTP `401`、`404`、`500`，并发布全局错误事件。
- HTTP `200` 中的非零业务 `status` 不触发全局拦截，由发起请求的业务模块按错误码处理。
- `err` 仅用于展示或诊断，不作为程序分支依据。

## 结果

- 新接口必须同时声明 HTTP 状态和业务错误码；不得再返回 HTTP `403`、`409`、`429`、`502`、`503`、`504` 作为业务 API 失败结果。
- OpenAPI 的 `200` 响应可能是成功体，也可能是接口声明的业务失败体。
- 全局事件监听者负责登录跳转、全局 404 页面或 500 提示；业务模块不重复实现这些跨应用动作。
- 该策略是项目协议约定，未来 Java 后端也必须保持一致。
