# ADR-0010：以数据库菜单树驱动导航并通过受控注册表加载页面

## 背景

前端导航和 Vue Router 子路由当前各维护一份静态配置，数据库菜单只用于 CRUD 展示，三者容易漂移。若直接把数据库字符串拼接为任意动态 import，又会把构建约束、模块边界和安全边界交给可变数据。

## 决策驱动因素

- 菜单、路由和用户角色授权使用同一数据库来源。
- 页面保持 Vite 可分析的代码分割和 Vue Router 正常导航能力。
- 数据库配置不能加载任意脚本或穿透业务模块内部。
- 新业务模块可以通过稳定公共入口接入，而无需修改应用壳组件。

## 考虑的方案

1. 继续分别维护静态路由与静态导航。实现简单，但数据库配置不会真正生效且长期存在双源漂移。
2. 把数据库中的文件路径直接交给动态 import。配置自由，但 Vite 无法可靠分析任意运行时路径，也扩大脚本加载与模块穿透风险。
3. 数据库保存稳定组件标识，前端组合根用受控注册表映射到各业务模块公开的懒加载器；导航树决定注册哪些路由。

## 决策

采用方案 3。登录后的导航树由数据库菜单、用户角色和角色菜单关系生成。`directory`、`menu`、`button` 分别表达目录、站内页面和外链动作。只有 `menu` 节点注册 Vue Router 路由；`button` 只允许 `http/https` 外链。

数据库 `component` 保存稳定标识，不保存可执行代码。前端 `view-registry` 只映射构建期由业务模块显式登记的页面懒加载器。未知标识不得回退到任意 import，也不得静默加载默认业务页。

登录和 404 页面仍是静态基础路由，因为它们必须在会话或数据库菜单不可用时可达。应用壳是静态父路由，业务子路由由菜单树动态注册。

## 正面结果

- 导航展示、站内路由与角色授权共享同一数据来源。
- 保留构建期代码分割、类型检查和模块公共入口。
- 错误菜单配置可被显式发现，不会成为任意脚本加载入口。
- 删除或停用菜单后，刷新会话即可撤销前端入口。

## 负面结果与风险

- 新页面仍需代码发布并登记组件标识，不能只写一条数据库记录就凭空生成页面。
- 首次进入受保护页面前增加一次导航树请求。
- 在线会话不会自动感知其他管理员刚完成的菜单变更，当前通过重新加载解决。

## 验证和复审条件

- 测试必须证明未知组件不注册路由、外链协议受限、目录不产生可点击站内路由。
- 当出现真正的低代码页面定义或远程模块联邦需求时，重新评估受控注册表边界及签名、沙箱和版本策略。

## 2026-07-27 补充：存量数据兼容边界

菜单写入契约负责阻止新的无效配置；菜单摘要读取契约允许返回旧版本遗留的字段组合，以便管理员修正。运行时导航是执行边界，只接收具备完整站内路由信息或合法 HTTP(S) 地址的节点。无效旧节点不会参与导航和动态路由，但也不会被系统自动删除或猜测性改写。

## 2026-07-27 补充：模块注册文件自动发现

ADR-0012 将中心文件逐项手工导入模块的实现替换为构建期自动发现 `src/modules/**/view-registry.ts`。这不改变本 ADR 的受控白名单边界：每个页面仍需在源码中显式登记并随前端发布，数据库字符串仍不能成为任意动态 import 路径。
