# 错误码参考

## 使用原则

- `status = 0` 只表示成功。
- 其他数值均表示错误，必须在本文档登记后使用。
- HTTP 状态码表达传输层结果，业务错误码表达可跨协议、跨后端实现保持稳定的业务原因。
- 前端根据数值错误码执行逻辑，不根据 `err` 文案做分支。
- `err` 不得包含堆栈、SQL、密码、令牌或内部系统地址。

## 通用错误码

| 错误码 | 常量 | 建议 HTTP 状态 | 含义 |
| ---: | --- | ---: | --- |
| 0 | `SUCCESS` | 2xx | 成功 |
| 1000 | `INVALID_REQUEST` | 400 | 请求参数、格式或校验失败 |
| 1001 | `UNAUTHORIZED` | 401 | 未登录、令牌缺失或无效 |
| 1002 | `FORBIDDEN` | 403 | 已识别身份但没有操作权限 |
| 1003 | `RESOURCE_NOT_FOUND` | 404 | 目标资源或路由不存在 |
| 1004 | `RESOURCE_CONFLICT` | 409 | 唯一约束、状态冲突或重复操作 |
| 1005 | `RATE_LIMITED` | 429 | 请求频率超过限制 |
| 9000 | `INTERNAL_ERROR` | 500 | 未分类的服务端内部错误 |
| 9001 | `EXTERNAL_DEPENDENCY_ERROR` | 502/503/504 | 数据库或外部服务不可用、超时或响应异常 |

代码定义位于 `apps/backend/src/shared/errors/error-codes.ts`。本文档与代码必须在同一个提交中更新。

## 区间分配

| 区间 | 用途 |
| --- | --- |
| 0 | 成功，禁止用于错误 |
| 1000-1999 | 全局通用请求、认证、权限和资源错误 |
| 2000-2999 | 用户与组织模块，启用前在此登记 |
| 3000-3999 | 订单或交易类模块，启用前在此登记 |
| 4000-8999 | 后续业务模块，按百位或千位登记边界 |
| 9000-9999 | 服务端基础设施和外部依赖错误 |

项目尚未实现具体业务模块，因此 `2000-8999` 当前没有实际错误码。新增模块时应先在本表登记模块范围，避免多人或 AI 重复分配。

## 新增错误码流程

1. 确认现有错误码不能准确表达场景，避免为同一含义重复创建。
2. 在本文件的区间表中确认模块范围。
3. 在 `error-codes.ts` 增加语义清晰的常量。
4. 在本文档表格增加数值、常量、HTTP 状态和含义。
5. 在 OpenAPI 的相关错误响应中增加说明或示例。
6. 增加后端错误路径测试和前端处理测试。
7. 运行 `pnpm test` 和 `pnpm build` 后提交。

## 响应示例

参数错误：

```json
{
  "status": 1000,
  "err": "Invalid request"
}
```

资源不存在：

```json
{
  "status": 1003,
  "err": "Resource not found"
}
```

内部异常：

```json
{
  "status": 9000,
  "err": "Internal server error"
}
```
