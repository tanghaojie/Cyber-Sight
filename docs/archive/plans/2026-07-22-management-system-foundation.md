# 管理系统基础能力实施计划

## 目标

交付具备统一软删除审计字段、会话认证、现代化管理框架及用户/角色/菜单/字典 CRUD 的可运行管理系统基线。

## 背景与设计依据

依据[管理系统基础能力设计](../design/management-system.md)、ADR-0001 至 ADR-0005 和仓库统一响应/HTTP 状态约定实施。

## 范围

OpenAPI 契约、Drizzle Schema/迁移、认证与管理 API、Vue 管理端框架和页面、自动化测试、视觉验证及文档收尾。

## 非目标

不实现注册、密码找回、组织/租户、多因素认证、细粒度按钮权限、生产部署和第三方身份提供商。

## 前置条件和风险

- 当前工作区无用户改动且无重复计划。
- 本机 PostgreSQL 可能不可用，因此默认验证不依赖真实数据库，迁移生成和可选数据库检查分开执行。
- 基线 `pnpm test/build` 在受限沙箱内因 esbuild 读取上级目录被拒绝，最终验证需使用已批准的非沙箱执行。

## 实施任务

- [x] 更新 OpenAPI 契约并生成共享类型。
- [x] 建立统一审计列、业务表和数据库迁移。
- [x] 实现认证领域服务、会话鉴权和管理资源仓储/API。
- [x] 实现登录页、应用框架、路由守卫和管理模块页面。
- [x] 补齐后端、前端、契约和 Schema 测试。
- [x] 运行生成、测试、构建和视觉检查。
- [x] 同步最终设计、日志、索引和迁移说明。

## 测试与验证

已执行 `pnpm gen:api`、`pnpm db:generate`、`pnpm test` 和 `pnpm build`。后端 32 项、前端 17 项测试通过，生产构建通过；浏览器完成桌面登录页、桌面管理框架和 390×844 窄屏布局检查。

## 发布与回滚

发布前执行数据库迁移并修改初始管理员密码。回滚代码时需同步回滚前端和后端；数据库迁移以向前修复为主，避免直接删除已产生的数据表。

## 实际偏差和遗留问题

初版设计计划使用 Fastify 注入覆盖全部数据库 CRUD；考虑默认测试不依赖真实 PostgreSQL，本轮改为由密码/令牌单元测试、全表 Schema 测试、Swagger 路径契约测试和前端状态测试组成。真实数据库迁移执行与集成回归保留为部署环境动作。细粒度 RBAC、组织/租户、404/500 全局页面和生产初始密码注入仍是后续事项。
