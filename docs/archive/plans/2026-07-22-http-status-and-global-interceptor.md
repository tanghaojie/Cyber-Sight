# HTTP 状态策略与前端全局拦截器实施计划

## 目标

后端除 401、404、500 外的错误统一返回 HTTP 200，并由业务状态码表达原因；前端集中拦截三种全局 HTTP 错误，其余错误由业务模块处理。

## 实施任务

- [x] 新增 ADR 并更新现有设计、错误码和维护指南。
- [x] 修改 Fastify 全局错误映射并补充测试。
- [x] 为 `openapi-fetch` Client 注册全局响应拦截器并补充测试。
- [x] 运行生成、测试、构建、数据库和文档验证。
- [x] 更新实际结果、归档计划并提交。

## 验证

- 401、404、500 保持对应 HTTP 状态和统一错误体。
- 参数、权限、冲突、限流、外部依赖等错误返回 HTTP 200 和非零业务状态。
- 前端只为 401、404、500 发布全局事件，其他响应不触发。
- `pnpm gen:api`、后端 16 个测试、前端 15 个测试、`pnpm build`、`pnpm test:db` 全部通过。

## 实际结果

- Fastify 全局错误处理先保留原始错误语义生成业务码，再将对外 HTTP 状态限制为 200、401、404、500。
- `openapi-fetch` Client 注册共享中间件，为 401、404、500 发布 `api:global-http-error` 事件。
- 业务模块继续处理 HTTP 200 中的非零 `status`，全局拦截器不处理这类响应。
- Vite 构建存在既有 CJS Node API 弃用警告，不影响交付。

## 回滚

回滚必须同时恢复后端状态映射、前端拦截器、测试和 ADR，不能只恢复单侧实现。
