# AI Git 暂存区门禁与提交署名

## 目标

把 AI 开始修改仓库前的暂存区检查，以及 AI 自动提交时的模型署名，固化为仓库级强制规则。

## 背景与设计依据

现有规则要求 AI 在任务完成且验证通过后提交改动，但没有防止 AI 在人类已有暂存内容的情况下开始工作，也没有要求 AI 提交可被明确识别和追溯。本次更新 `docs/design/documentation-governance.md`，让 Git 工作流门禁成为当前有效的协作治理设计。

## 范围

- 更新根目录 `AGENTS.md`，增加开始工作前的暂存区硬门禁。
- 规定门禁失败时必须停止修改，并要求人类先提交已有暂存内容。
- 规定 AI 自动提交的 `Co-Authored-By` trailer 格式和真实模型名要求。
- 更新文档治理设计、计划索引和 AI 协作日志索引。

## 非目标

- 不改变人类提交的署名要求。
- 不替人类提交、取消暂存或改写任务开始前已有的暂存内容。
- 不修改业务源码或引入 Git hook。

## 前置条件和风险

- 任务开始时必须先确认 `git diff --cached --quiet` 成功；本轮检查结果为空。
- Git hook 无法可靠判断提交者是否为 AI，本约束通过仓库级 AI 指令强制执行。
- 暂存 AI 本轮改动用于最终提交不属于门禁失败；门禁检查发生在首次仓库修改之前。

## 实施任务

- [x] 检查任务开始时的 Git 暂存区和工作区状态。
- [x] 阅读文档治理设计、相关索引和现有提交约定。
- [x] 更新仓库级 AI 规则和文档治理设计。
- [x] 更新计划、AI 日志及相关索引。
- [x] 验证规则措辞、Markdown 和 Git diff。
- [x] 归档计划并准备创建带 AI 模型署名的提交。

## 测试与验证

- `git diff --cached --quiet` 在首次修改前和实施期间均成功，确认没有既有暂存内容混入。
- 关键规则搜索通过，`AGENTS.md` 和文档治理设计均覆盖检查命令、停工行为、禁止绕过、真实模型名称和提交后验证。
- `git diff --check` 通过，仅出现仓库既有换行符转换提示。
- 变更范围检查确认只修改治理文档，没有修改业务源码。
- 提交创建后使用 `git log -1 --format=full` 验证 trailer 包含真实模型名 `GPT-5`。

## 发布与回滚

规则随 Git 提交生效。若后续调整协作政策，应同步修改 `AGENTS.md`、文档治理设计和相关日志，不通过绕过门禁临时处理。

## 实际偏差和遗留问题

- 按计划未引入 Git hook；Git hook 无法可靠识别人类提交和 AI 提交，仓库级 AI 指令是本次约束载体。
- 将门禁适用范围明确为任何可能修改代码或仓库文件的 AI 任务，比仅检查业务代码更严格，可避免文档或配置改动混入人类暂存内容。
- 没有遗留问题。
