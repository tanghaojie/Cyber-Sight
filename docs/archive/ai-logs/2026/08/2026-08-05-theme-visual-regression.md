# 主题视觉回归修复协作记录

## 用户反馈

- 除绿色外，其余主题与深色模式组合不协调。
- 黑白灰、蓝、紫、橙的深色背景没有生效。
- 首页 Hero、侧栏品牌区和登录页仍固定为绿色。
- 健康检查前端状态未完整跟随主题色。
- 用户允许使用浏览器测试和验收。

## 根因

- `:root[data-theme]` 的选择器优先级高于通用 `html.dark`，主题的浅色表面覆盖了深色表面。
- Hero、品牌氛围和部分状态光晕仍直接写入初始绿色 RGB 值，未消费语义主题令牌。
- 主题模型只定义基础主色，缺少深色表面、品牌背景、Hero 和状态等组件级语义令牌。

## 方案

把主题定义扩展为完整的双模式视觉系统。组件只消费语义令牌；每套深色主题独立校准冷暖、明度和对比度，语义错误/警告仍保留稳定状态色。

## 验证记录

- 重新设计翡翠绿、政务红、高级黑白灰、智蓝、灵感紫和琥珀橙的浅色/深色色板，并用组件级语义令牌统一画布、面板、品牌、Hero 与状态视觉。
- 修正深色选择器优先级后，浏览器读取到六套不同的深色画布：`#0d1511`、`#160f11`、`#10100f`、`#0b1218`、`#120f17`、`#15110c`；浅色画布亦逐项切换成功。
- 浏览器确认首页 Hero、侧栏背景与品牌标识、健康状态指示、深色登录页和设置弹窗均使用当前主题色；跨登录页与首页的路由切换仍保留主题选择。
- `pnpm format`、`pnpm format:check`、`pnpm lint` 与 `pnpm build` 均通过。构建仅保留既有 Sass legacy JS API、pure annotation 与静态/动态导入提示，不影响本次交付。

## 偏差与遗留

- 前端仓库不维护自动化 UI 测试；本次按用户授权采用浏览器人工验收，不新增浏览器测试文件。
- 未新增 ADR；本次属于既有主题能力的视觉修正，长期约束已同步至现行模块与品牌设计文档。
