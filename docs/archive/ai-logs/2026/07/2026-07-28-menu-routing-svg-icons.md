# 菜单分层路由与 SVG 图标注册表

## 用户目标和约束

用户要求目录与菜单都配置站内路径，只有根节点强制 `/` 开头；取消菜单编码配置；把 `AppIcon.vue` 的内联 SVG 拆分并由 Vite 插件自动加载；菜单图标改为下拉选择。任务以 `apps/frontend` 体验为目标，但必须保持共享契约和后端运行时校验一致。

## 关键问答与确认

无需额外问答。仓库检查表明目录路径会被当前 Zod Schema 拒绝，子节点相对路径会被后端过滤，因此同步调整契约和后端属于需求的必要链路。

## AI 的重要假设

- 非根节点以 `/` 开头时表示绝对路径覆盖；不以 `/` 开头时拼接上级目录路径。
- 目录只提供路径前缀和布局上下文，不变成可点击页面。
- `code` 暂时作为后端兼容键保留，但不再展示或允许用户编辑；新建节点生成内部唯一值。
- 存量空目录路径作为透明前缀兼容，新的目录写入必须提供路径。

## 方案和执行摘要

已完成共享菜单路径校验、后端父级规则校验、前端分层路径解析和动态路由注册。目录与菜单现在都必须填写站内路径；根节点必须以 `/` 开头，子节点可使用相对路径或绝对路径。

前端菜单表单不再暴露 `code`，新建节点生成内部兼容键；图标输入改为可搜索下拉框。原 `AppIcon.vue` 内联图形已拆为 20 个 SVG 文件，通过 `vite-plugin-svg-icons` 生成 sprite 和名称注册表，Vite 与 Vitest 使用同一配置。

运行报错排查中补充了虚拟模块类型声明和显式 `fast-glob` 依赖，并兼容 Vitest 的双层 `default` 模块包装。

## 验证结果

- `pnpm test` 通过：API 契约检查通过，后端 54 个测试、前端 41 个测试通过。
- `pnpm build` 通过：API 契约、后端和前端生产构建通过。
- 浏览器验证通过：菜单列表图标、图标下拉、目录路径字段、根节点和子节点路径提示均符合设计，未提交测试表单数据。
- `git diff --check` 通过。
