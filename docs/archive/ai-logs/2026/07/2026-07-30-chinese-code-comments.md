# 补充中文代码注释

## 用户目标和约束

- 用户已确认功能正常，希望在不依赖设计文档的情况下能够从代码梳理模块逻辑。
- 为源码补充必要注释，注释必须使用中文。
- 遵守既有人工修改优先、文档门禁、格式验证和 AI 提交规则。

## 关键问答与确认

- 无额外问答；按“解释职责、数据流、约束和原因，不逐行翻译语法”的原则实施。

## AI 的重要假设

- “注释都补上”指覆盖所有主要代码区域的必要注释，不要求给每个导入、简单赋值和模板语句添加重复性注释。
- 本轮仅增强可读性，不改变任何运行行为或公共契约。

## 方案和执行摘要

- 在现行开发工作流中新增中文代码注释规范，明确必需位置、语言和反复述原则。
- 为共享 HTTP/Zod 契约、后端组合根、认证、授权、数据库、仓储、路由和测试补充职责与约束说明。
- 为前端启动、HTTP 错误、会话 Store、动态路由、注册表、布局、菜单树和各管理页面/弹窗补充数据流与状态说明。
- 复查所有 TypeScript、Vue 和后端测试文件的注释覆盖，并确认差异未改变运行逻辑。

## 验证结果

- `pnpm format`：通过。
- `pnpm lint`：通过。
- `pnpm format:check`：通过。
- `pnpm test`：11 个测试文件、86 个测试全部通过。
- `pnpm build`：契约、后端和前端全部构建成功。
- 前端未运行自动化或浏览器测试，符合仓库人工验收边界；用户已在任务开始前确认现有功能正常。
